# 화학안전 계획서 작성지원 (planner)

**화학사고예방관리계획서**(화학물질관리법 시행규칙 별지 제1호~제16호)를 사람이 최소한만 입력해서 작성하도록 돕는 Streamlit 프로그램입니다. 공정안전보고서(PSM)는 기존 방식으로 유지되며 같은 방식으로 다시 만들 예정입니다.

## 만든 철학

1. **사람은 프로그램이 알 수 없는 것만 입력합니다.** 계산·조회·규정에서 나오는 값은 자동으로 채웁니다.
2. **한 번 입력한 사실은 다시 묻지 않습니다.** 별지 제1호에서 적은 시설·물질 정보는 이후 별지(제2~16호)로 흘러 들어갑니다.
3. **단계마다 쉬운 말 설명**을 붙입니다. 칸마다 무엇을 왜 적는지 알 수 있어야 합니다.
4. **마지막에 규정서식 DOCX**를 내려받습니다. 별지 순서(1→16)대로 작성합니다.
5. **법령 우선**: 자료가 서로 다르면 `시행규칙 > 작성 규정 고시·화학물질안전원 지침 > 작성 매뉴얼 > 기존 프로그램(KORA)` 순으로 따릅니다.
6. **결과가 규정과 맞는 것이 목표**입니다. KORA의 알고리즘을 따라 하지 않고, 자체 계산으로 같은 결과를 냅니다.

## 사용 흐름

```text
화학사고예방관리계획서 작성 (기본 화면)
  ├─ 새 사업장으로 시작하기: 사업장 + 물질 몇 가지 입력 → 법정 대상 판정(1군·2군일 때만 진행)
  ├─ 별지 선택 (제1호 ~ 제16호)
  │    제1호는 "1. 시설 입력 → 2. 결과 → 3. 서식 내보내기" 3단계
  ├─ 엑셀 양식 내려받기·올리기 (선택)
  └─ 서식 내보내기: 규정서식 DOCX
공정안전보고서 (기존 방식): 판정진단 → 작성범위 선택 → 통합 작성자료 → 점검·보완 → 보고서 작성
참고: 규정 DB 관리, 법령·근거 라이브러리
```

- "시작하기"는 기존 Stage 1 판정 엔진과 법령 최신성 확인을 그대로 씁니다. 법정 대상(1군·2군)이 아니면 작성을 시작하지 않고, 승인 규정 DB가 없으면 시스템 안내에서 멈춥니다(fail-closed).
- 별지 제1호 시설 입력에는 물질 표, 시설 그리드, 계산 미리보기가 첫 화면에 있습니다.

## 별지별 자동화

| 별지 | 내용 | 자동으로 하는 일 |
|---|---|---|
| 제1호 | 작성수준 구분 | 물질·시설·최대보유량에서 규정수량 비교, 1군·2군 산정 |
| 제2호 | 변경내역 관리대장 | 변경 사실 기록 |
| 제3~5호 | 시설 개요, 설비·배관 | 제1호 시설 행에서 자동 전개 |
| 제6·7호 | 물질 정보(MSDS) | 대표물질(최대 2개) 정리, 제7호 행 구성 |
| 제8호 | 보호대상 등 주변 환경 | 좌표 조회(Kakao), 500 m 범위 목록, 체크박스 |
| 제9호 | 설비 명세 | 설비 사양 표를 제1호 시설과 연동, 단위 환산 |
| 제10·11호 | 시나리오 관련 | 예비시나리오 선정(별표 2 규정수량), 누출·확산 계산 결과 연결 |
| 제12·13호 | 영향범위 | 끝점농도 표, 독성 확산·화재·폭발 계산 |
| 제14호 | 사고빈도 | 별지 제14호 빈도값 적용 |
| 제15·16호 | 위험도·완료 | 영향범위·인구 기준 위험도 판정 |

## 계산의 근거

- **끝점**: 화학물질안전원 기술지침 제2021-3호. 독성 ERPG-2 → AEGL-2 → PAC-2 → IDLH×0.1 순, 폭발 1 psi, 화재 40초 5 kW/m².
- **기상조건**: 3 m/s D등급(일반), 1.5 m/s F등급(최악).
- **누출**: KOSHA GUIDE P-92-2023 식(염소 예제로 검증), 누출공은 가장 큰 연결구 지름의 20%(예외 있음), 액체층 1 cm, 방류벽 면적 반영.
- **확산**: Briggs 도심·교외 가우시안 플룸, 액체 웅덩이 증발(EPA RMP), TNT 등가 폭발.
- **판정**: 별표 3 점수 기준(합계 10 이상 가, 6 이상 나, 그 외 다).
- 근거 문서 목록은 `data/stage2/cap_forms/basis_guides.json`, 끝점표는 `data/stage2/cap_endpoints/`에 있습니다.

### 알려진 한계 (전문가 검토 필요)

- 밀도가 높은 가스 효과, BLEVE·TNO 다중에너지, 2상 비평형 방출은 모델에 넣지 않았습니다.
- API 581 누출지속시간 표는 미검증 참고값입니다.
- 지형·풍향은 반영하지 않고 원형(보수적)으로 계산합니다.
- 붙임 4 증발계수는 PDF에서 읽을 수 없어 EPA 식을 kg/m²로 환산해 썼습니다.
- 화면의 설명문은 초안이며 전문가 검토가 필요합니다.
- Kakao·KOSHA·코샤가이드 API는 실제 키로 호출해 검증하지 못했습니다.

## 구조

```text
app.py                          내비게이션(CAP 기본, PSM 기존 방식, 참고)
ui/cap_workspace_page.py        CAP 작성 화면
ui/cap_start_panel.py           시작하기(판정 후 프로젝트 생성)
ui/cap_form{2..16}_view.py      별지별 화면, cap_forms_registry.py가 목록 관리
ui/cap_excel_panel.py           엑셀 양식 다운로드·업로드
ui/cap_frames.py                Arrow 안전 표 출력
engine/stage2/cap_start.py      시작하기 로직
engine/stage2/cap_shared_facts.py 별지 간 공유 사실
engine/stage2/cap_form*_workspace.py 별지별 로직
engine/stage2/cap_release*.py, cap_dispersion.py, cap_fire.py 누출·확산·화재·폭발
engine/stage2/cap_endpoints.py  끝점농도
engine/stage2/cap_baseline_docx.py 규정서식 DOCX 생성
engine/kosha_guide.py           코샤가이드 조회
data/stage2/cap_forms/          별지 화면 스키마(form01~16.json)
```

화면은 별지 서식 파일(별지만 든 문서)이 정하고, 별표는 프로그램이 배우는 지식으로 씁니다.

## 데이터 상태

`Stage2Project.fields`에 사실을 저장하고 각 값에 상태를 붙입니다.

- `VERIFIED` 근거와 함께 확인됨 / `USER_CONFIRMED` 담당자 확인 / `CALCULATED` 계산 산출
- `AI_DRAFT` 사람 검토 전 초안 / `HOLD` 미확인

저장 위치는 `data/runtime/stage2/projects/<project_id>/`이며 회사 자료는 Git에 올리지 않습니다. DOCX가 만들어져도 제출 확정본으로 보지 않으며, 제출 전 담당자가 회사 사실과 대조해야 합니다.

## 공정안전보고서(기존 방식)

법적 대상 판정(대상업종, 시행령 별표 13 규정량, 합산 R값 등)과 Stage 2 자료준비·교차검증·DOCX 작성이 그대로 남아 있습니다. HOLD-first 원칙(법령 최신성·승인 DB·물질 식별이 불확실하면 확정하지 않음)도 유지됩니다. 자세한 정책은 `docs/`를 보세요. CAP 방식으로 재작성한 뒤 옛 단계를 정리할 계획입니다.

## API 설정

프로젝트 루트 `.env`에 입력합니다(GitHub에 올리지 마세요).

```text
LAW_OC=국가법령정보_공동활용_인증값
KOSHA_MSDS_SERVICE_KEY=공공데이터포털_인증키   # MSDS 참고 조회 및 코샤가이드 조회
KAKAO_REST_API_KEY=카카오_REST_API_키          # 별지 제8호 주소 좌표 조회(선택)
```

키가 없으면 해당 조회는 하지 않고 직접 입력으로 넘어갑니다. KOSHA MSDS 조회값은 회사 제품 SDS를 대체하는 법적 근거가 아닙니다.

## 실행과 테스트

```bash
pip install -r requirements.txt
streamlit run app.py
python -m pytest -q
```

PR과 `main` push에서 CI가 전체 테스트를 실행합니다. 화면 렌더 확인은 `PYTHONPATH=. python tests/smoke_cap_views.py [project_id]`로 할 수 있습니다.

## 앞으로

- PSM을 같은 방식(최소 입력·자동 연동·즉시 서식 미리보기)으로 재구축하고 옛 3~5단계 제거
- 작성 매뉴얼의 기술지침 인용 연결
- BLEVE·TNO·2상 방출 모델, 물성 DB
- 실제 API 키로 검증, 설명문 전문가 검토
