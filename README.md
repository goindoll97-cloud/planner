# 화학안전 계획서 작성 지원 시스템 (planner)

기업의 **공정안전보고서** 및 **화학사고예방관리계획서** 대상 여부를 먼저 보수적으로 판정하고, 대상인 경우에만 사용자가 이번 프로젝트에서 실제로 작성할 문서를 선택한 뒤 필요한 자료·법적 근거·관련 서식을 안내하고 작성·검증을 지원하는 Streamlit 기반 시스템입니다.

## 핵심 원칙

1. **Rule Engine 우선**: 법적 대상 여부를 AI가 추측하지 않습니다.
2. **HOLD-first**: 법령 최신성, 승인 규정 DB 출처, 물질 식별, 수량·조건 중 하나라도 불확실하면 확정판정을 하지 않습니다.
3. **법적 대상 여부와 작성범위 분리**: Stage 1에서 공정안전보고서 제출 대상으로 판정되더라도 사용자가 이번 프로젝트에서 공정안전보고서 작성 지원을 선택하지 않을 수 있습니다. 이 선택은 법적 대상 판정을 변경하지 않습니다.
4. **기존 자료 우선 활용**: Stage 1 또는 Stage 2에서 이미 확인된 회사자료는 다시 요구하지 않습니다.
5. **자료접수와 내용확인 분리**: 파일이 업로드되었다고 해서 자동으로 내용이 확인된 것으로 처리하지 않습니다.
6. **부족자료는 근거와 함께 요청**: 부족하거나 판단할 수 없는 항목은 작성근거, 관련 법정 별지서식, 작성매뉴얼·작성예시의 관련 위치와 함께 안내합니다.
7. **법령 용어 우선**: 사용자 화면, registry 표시명, XLSX 및 문서에서는 법령·시행령·시행규칙·현행 고시의 정식 명칭과 표현을 우선합니다.
8. **AI 초안과 확인사실 분리**: `AI_DRAFT`는 사람 검토 전까지 완료로 인정하지 않습니다.
9. **증빙 추적**: 업로드 자료는 SHA-256과 함께 기록합니다.

## 법령 용어 사용 우선순위

```text
법률·시행령·시행규칙
        ↓
현행 행정규칙·별표·별지
        ↓
공식 작성매뉴얼·안전보건기술지침
        ↓
내부 보조용어
```

내부 코드 식별자는 호환성을 위해 `PSM`, `CAP` 등을 유지할 수 있으나 사용자에게 노출되는 문구는 정식 명칭을 사용합니다.

공정안전보고서의 상위 작성구조는 다음과 같이 관리합니다.

- 공정안전자료
- 공정위험성평가서
- 안전운전계획
- 비상조치계획

화학사고예방관리계획서의 작성구조는 다음과 같이 관리합니다.

- 기본정보
- 시설정보
- 장외평가정보
- 사전관리방침
- 내부 비상대응계획
- 외부 비상대응계획

## 사용자 흐름

사이드바는 다음 순서로 구성됩니다.

1. `✅ 1. 판정진단`
2. `🧭 2. 작성범위 선택`
3. `📥 3. 자료준비·접수`
4. `🔎 4. 작성자료 교차검증`
5. `📝 5. 작성·검토`
6. `🗂️ 6. 규정 DB 관리`
7. `📚 7. 법령 근거`

전체 흐름은 다음과 같습니다.

```text
Stage 1 법적 대상 여부 판정
        ↓
작성 프로젝트 생성
        ↓
이번 프로젝트 작성범위 선택
        ↓
선택한 문서의 작성항목·근거·관련 서식 안내
        ↓
회사 보유자료 우선 업로드
        ↓
확인 / 일부 확인 / 사람 확인 필요 / 자료 요청 필요 분류
        ↓
부족자료를 작성근거·관련 법정 서식과 함께 재요청
        ↓
작성자료 교차검증
        ↓
확인사실 기반 작성·검토
        ↓
최종 검증 후 제출 산출물 생성(후속 단계)
```

## Stage 1 판정엔진

### 중앙 readiness gate

다음 조건이 모두 충족되어야 판정을 시작합니다.

```text
공식 현행 법령 조회 성공
        ↓
법령·행정규칙 및 첨부 PDF 상태 = CURRENT
        ↓
필수 승인 규정 DB 존재
        ↓
승인 DB의 근거 PDF SHA-256 확인
        ↓
현재 공식 PDF SHA-256과 일치
        ↓
ALLOW
```

하나라도 충족되지 않으면 `HOLD` 처리합니다.

### 공정안전보고서 판정

현재 구현 범위에는 대상업종 확인, 시행령 별표 13 규정량 매칭, 순도·농도 조건, 동일 법적 항목 선합산, 제조·취급 및 저장 기준 비교, 비고 제7호 합산한 값(R), 비고 제8호 제외수량, 특수 성분조건, 제외설비 확인 등이 포함됩니다.

### 화학사고예방관리계획서 판정

현재 구현 범위에는 사고대비물질 우선 판정, 직접 CAS 및 포괄 법적 물질범위, 유해성·위험성 그룹 보완 판정, 사업장 최대보유량, 하위·상위 규정수량 비교, 면제시설, 주요취급시설, 1군 사업장·2군 사업장 판정 등이 포함됩니다.

## Stage 2 작성범위 선택

`Stage2Project`는 다음을 분리해 저장합니다.

```text
psm_required / cap_required
→ Stage 1의 법적 대상 여부

psm_selected / cap_selected
→ 이번 작성 프로젝트의 지원 범위
```

예를 들어 공정안전보고서와 화학사고예방관리계획서 모두 법적 대상이더라도 화학사고예방관리계획서만 선택할 수 있습니다. 이 경우 공정안전보고서의 법적 대상 상태는 그대로 보존됩니다.

## Stage 2 자료준비·접수

선택한 작성범위의 registry를 기준으로 다음 정보를 표시합니다.

- 작성구조
- 작성항목
- 현재 자료상태
- 현재 확인되지 않은 내용
- 확인 가능한 회사자료 예
- 작성근거
- 관련 법정 별지서식
- 작성매뉴얼 또는 작성예시 관련 위치

자료상태는 프로그램 내부 업무상태이며 법령 용어가 아닙니다.

- `확인`
- `일부 확인`
- `사람 확인 필요`
- `자료 요청 필요`
- `해당 없음`

회사 파일을 업로드했다고 해서 자동으로 `VERIFIED` 처리하지 않습니다. 담당자가 해당 내용의 포함 여부를 직접 확인하지 않은 경우 파일은 접수하되 `HOLD` 상태로 남겨 사람 확인이 필요함을 표시합니다.

### 프로그램 입력양식과 법정 서식 구분

자료준비 화면에서 내려받는 XLSX는 **프로그램 입력양식**이며 법정 별지서식이 아닙니다. 법정 별지서식이 있는 작성항목은 관련 별지서식 번호를 별도로 표시하고 현행 법령·고시 원문 확인을 요구합니다.

## Stage 2 교차검증

현재 자동검증 범위는 다음과 같습니다.

- 기술자료의 근거파일 연결 여부
- 첨부자료 SHA-256 형식
- 상호검증 자료 준비 여부
- 구조화 설비자료의 설비 식별번호 중복
- 설비목록 ↔ 설비명세 식별번호 비교
- 설비명세 ↔ 안전밸브·파열판 보호대상 설비 비교
- 화학물질 목록 ↔ 화학사고예방관리계획서 유해화학물질 상세 명세 CAS 번호 비교

P&ID, PFD, 공정위험성평가서 및 자유서술 문서의 내용을 구조화하지 않은 상태에서는 AI가 내용을 추정하여 일치 여부를 확정하지 않습니다.

## 작성자료 상태

- `VERIFIED`: 근거자료와 함께 확인된 사실
- `USER_CONFIRMED`: 담당자가 직접 확인한 사실
- `CALCULATED`: 검증된 계산엔진으로 산출한 값
- `AI_DRAFT`: AI 초안이며 사람 검토 필요
- `HOLD`: 미확인 또는 근거 부족

이 상태값은 법령상의 판정용어가 아니라 프로그램 내부 상태입니다.

## 저장과 증빙

```text
data/runtime/stage2/projects/<project_id>/
├─ project.json
└─ attachments/
```

업로드 증빙에는 SHA-256을 기록합니다. 실행 중 생성되는 회사자료와 법적 근거 보관자료는 Git에 커밋하지 않습니다.

## 현재 산출물

현재 단계에서는 다음 검토용 산출물을 제공합니다.

- 프로젝트 원본 JSON
- 자료준비용 프로그램 입력양식 XLSX
- 작성현황·근거·요청자료 XLSX
- 교차검증 결과 JSON

법정 제출용 최종 DOCX/PDF/XLSX/ZIP은 세부 계산·문서작성·최종 validation gate를 완성한 뒤 활성화합니다.

## API 설정

프로젝트 루트의 `.env`에 인증값을 입력합니다.

```text
LAW_OC=국가법령정보_공동활용_인증값
KOSHA_SERVICE_KEY=KOSHA_MSDS_API_인증값
```

`.env`와 Streamlit secrets는 GitHub에 올리지 않습니다.

## 실행

```bash
pip install -r requirements.txt
streamlit run app.py
```

## 테스트

Pull Request와 `main` push에서 다음을 수행합니다.

1. Python 소스 compile check
2. 전체 `unittest` 실행

작성범위 선택이 법적 대상 여부를 변경하지 않는지, 선택하지 않은 문서가 요청자료·작성률·교차검증에 포함되지 않는지, Stage 1 확인자료가 재요청되지 않는지, 법정 서식과 프로그램 입력양식이 구분되는지 등을 회귀테스트로 확인합니다.
