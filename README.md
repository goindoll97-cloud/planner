# 화학안전 계획서 작성지원 (planner)

**화학사고예방관리계획서**(화학물질관리법 시행규칙 별지 제1~16호)와 **공정안전보고서**(산업안전보건법, 고용노동부고시 별지 제12~21호)를
**회사 파일을 올리면 프로그램이 읽고 직접 작성해 주는** Streamlit 프로그램입니다. 사람은 서식을 채우지 않습니다.
파일을 올리고, 프로그램이 알려 주는 "어느 파일의 무엇이 잘못됐는지"를 고쳐 다시 올리면 됩니다.
계산·조회로 나오는 값은 자동으로 채우고, 마지막에 규정서식 초안을 내려받습니다. HWP는 원본서식에 사업장 일반정보 일부를 직접 작성한 시험 초안을 제공합니다.

## 만든 철학

1. **사람은 서식을 쓰지 않고 파일을 올립니다.** 프로그램이 회사 파일에서 법정서식에 맞는 값을 찾아 직접 채웁니다.
2. **잘못된 곳은 파일 단위로 알려 줍니다.** 값이 부족하거나 충돌하거나 단위·형식이 틀리면 "어느 파일의 어느 항목이 왜 문제인지"를 알려 줍니다.
   사람은 그 파일을 고쳐 다시 올립니다. 화면에서 서식 칸을 직접 고쳐 쓰는 경로는 두지 않습니다.
3. **자료 접수 화면이 곧 작성 안내입니다.** 어떤 파일에 어떤 항목이 들어 있어야 하는지를 먼저 보여 주므로, 신입사원도 무엇을 준비할지 알 수 있습니다.
4. **한 번 올린 사실은 다시 묻지 않습니다.** 시설·물질·시나리오는 두 문서가 공유하고, 기상값은 주소로 자동 산정합니다.
5. **법령 우선**: 자료가 서로 다르면 `시행규칙·고시 > 화학물질안전원·KOSHA 기술지침 > 작성 매뉴얼 > 기존 프로그램(KORA)` 순으로 따릅니다.
6. **AI는 글만 씁니다.** 법적 대상 판정과 숫자 계산은 규칙 엔진이 합니다. 서술형은 회사 파일에서 읽은 사실만으로 초안을 쓰고,
   근거가 없는 부분은 `[확인 필요]`로 남기며, 초안 문서에 ‘AI 초안’으로 표시합니다. 결과물은 늘 초안이고 프로그램 안에 승인 절차는 두지 않습니다.
7. **근거 없는 값은 채우지 않습니다.** 자료에서 확인되지 않은 칸은 빈칸 또는 `[확인 필요]`로 남기고, 어느 파일을 보완해야 하는지 알려 줍니다.

## 화면과 개발의 기준: 회사는 파일만 고치고, 프로그램이 작성한다

이 원칙은 이후 화면·엑셀 양식·AI 기능을 변경할 때도 지킨다. 기능을 더하기 전에 사용자가 해야 할 일과 중복 화면을 줄일 수 있는지 먼저 확인한다.

- **보완 안내는 한곳, 한 표에 모은다.** ② 파일별 보완 요청의 ‘화학사고예방관리계획서에 필요한 사실’ 표에 누락·충돌·읽기 오류와 파일별 수정 요청을 함께 담는다. 실제 올린 파일명을 표시해 어느 파일을 고칠지 알 수 있게 한다. 원본을 특정하지 못하면 파일명을 추측하지 않는다.
- **표에는 다음 행동에 필요한 정보만 둔다.** 상태·사실·쓰이는 곳·올린 파일·고칠 점을 기본으로 한다. 값·출처·필요 열, 대상별 표, 계산·조회·지도 조사 값의 별도 박스를 자료 보완 화면에 중복해서 늘리지 않는다. 출처와 계산 근거는 내부에 보존하고 관련 결과 화면에서 확인할 수 있게 한다.
- **수정본은 회사 작성용 엑셀 전체를 받는다.** ①에서는 제공된 `.xlsx` 양식 한 파일만 받는다. 이름이 달라도 성공적으로 읽은 최신 엑셀로 교체하며, 삭제한 행과 비운 값도 이전본에서 가져오지 않는다. 양식 손상·다른 파일 형식이면 이전 반영본을 유지하고 이유를 알린다. 기존 자료와 원본은 이력에 보존한다. 수정 사유는 요구하지 않는다.
- **양식 이름은 ‘빈칸 전용 엑셀 양식’이다.** 필요한 빈칸을 채우는 보조 수단으로 제공한다. 별도 안내 시트를 만들지 않고 각 입력 시트에 예시 열을 둬 값을 보면서 작성하게 한다. 예시는 회사 사실로 읽거나 계산·초안에 반영하지 않는다. 채운 파일은 이름 그대로 ①에 다시 올린다.
- **회사 작성용 전체 엑셀은 이미 입력한 항목도 생략하지 않는다.** 단답형은 한 시트의 항목·값·예시 세 열에 모으고 관련 내용을 붙여 배열한다. 열 구조가 다른 반복 목록만 분리한다. 1군 전용·단위·확인 방법은 예시와 셀 메모로 안내한다. 계산 결과·법적 판정·완성된 계획서·도면이나 스캔자료의 제출란은 요구하지 않는다. 원본자료 업로드 기능을 대체할 때도 회사 사실, 혼합제품의 모든 구성성분, 현장 확인값이 빠지지 않도록 검증한다.
- **③ 시나리오 후보는 인식된 자료의 후보 표에 집중한다.** 표 아래에 조합별 메뉴·보완 경고·추가 확인 박스를 반복해서 쌓지 않는다. 부족한 자료와 고칠 점은 ②로 모은다.
- **④ 작성·내려받기는 작성 동작과 짧은 진행 상태에 집중한다.** ‘작성하기’와 서술형 AI 작성 기능을 중심으로 두고, 서술형 작성 중에는 전체 대상 수·완료 수·현재 항목·진행률을 표시한다. 진행률은 실제 항목 처리 기준이며 시간 예측값은 아니다. 앞 단계의 사실 표·보완 요청·설비 목록을 다시 펼치지 않는다.
- **다운로드는 ④에서 한 번에 제공한다.** 별도 ‘초안 내려받기’ 메뉴 없이 규정서식과 현재 작성된 서술형을 하나의 초안으로 내려받는다. DOCX 초안은 내려받을 수 있다. HWP는 원본서식에 사업장 일반정보 일부만 직접 작성한 시험 초안을 제공하며 미작성 범위를 명시한다. 서술형 포함 여부를 다시 묻지 않고, 버전·작성수준·첨부·행정서식 설정을 이 단계에 반복하지 않는다. 생성 전에 내부 검증을 실행하며 보완 내용은 ②의 한 표에 모은다. 검증 실패와 자료 부족을 구분하고 결과물은 항상 초안으로 표시한다.
- **완성된 계획서를 회사에 필수로 요구하지 않는다.** 회사는 연락기관·소통 대상·방법·주기·대피장소 등 단답형 사실을 제공하고, 프로그램은 그 사실로 소통·공조·대피 등 서술형 계획의 초안을 작성한다. 자료 접수·② 보완 표·빈칸 전용 엑셀 양식도 결과물 문장 대신 필요한 사실만 요청한다. 기존 계획서가 있으면 선택적으로 활용한다.
- **준비자료는 처음 맡는 사람도 찾을 수 있게 안내한다.** 파일 형식보다 누구에게 무엇을 확인할지 구체적으로 적는다. 회사가 협의할 일정의 예시를 법정 주기로 표시하지 않고, 지역사회 소통·법정 고지·사고 시 경보를 구분한다. 규정서식에서 횟수를 제시하지 않는다는 설명을 모든 관련 법령에 의무가 없다는 뜻으로 넓히지 않는다.
- **LLM은 필요한 서술형에만 최소한으로 쓴다.** 파일 인식·사실 연결·법적 판정·수치 계산은 규칙과 코드가 맡는다. 회사 사실로 규칙 초안을 먼저 만들고, 필요한 서술형에 한해 로컬 AI로 다듬는다. 전체 파트를 매번 LLM으로 다시 작성하지 않는다. 근거 없는 내용은 채우지 않는다.
- **제출 이후 관리는 한 화면으로 잇는다.** 독립된 버전 관리 메뉴 대신 ‘제출·이행 관리’에서 제출본 저장 → 제출서식 → 이전 제출본과 비교 → 이행점검을 처리한다. 사업장과 기준 제출본을 재사용하고 저장·비교·복원·법령 개정 반영과 기존 기록은 보존한다. 제출본 저장은 프로그램 안의 자료 보존이며 실제 제출·접수나 적합통보를 뜻하지 않는다.
- **규정서식의 명칭과 입력 칸을 구분한다.** 사용자가 제공한 DOCX의 표·병합·배경·명칭을 기준으로 한다. 색 있는 칸에는 값을 넣지 않고 지정된 흰색 기재란만 채운다. 제목 뒤에 답을 붙이거나 체크박스·표 머리글을 요약문으로 바꾸지 않는다. 첨부된 작성 예는 위치 확인용이며 예시 물질·수치·고유번호를 다른 사업장의 사실로 남기지 않는다. 서식 검증은 명칭 보존·입력 좌표·병합 폭·시나리오별 표 반복을 함께 확인한다.
- **같은 일을 하는 화면과 처리 경로를 늘리지 않는다.** 기존 파일 읽기·교체·초안 작성 경로를 재사용한다. 화면을 줄일 때에도 원본·출처·충돌 검사·법령 검증은 유지한다. 테스트는 옛 화면의 박스 개수보다 실제 파일 갱신, 예시 제외, 사실 기반 작성이 되는지를 검증한다.

## 사용 흐름

```text
① 회사 작성용 엑셀 내려받기·작성·올리기 → ② 시트·셀별 누락·입력 오류 확인
   → 수정한 엑셀 전체를 다시 올려 최신본으로 교체 → ③ 시나리오 후보 → ④ 초안 작성·내려받기
```

기본 시작 화면은 **사업장 업무**입니다. 별도 ‘새 사업장 만들기’ 코너 없이 엑셀의 사업장명으로 자료를 구분하고, 처음 올리는 사업장은 읽기 성공 후 자동 등록합니다. 자료 접수에서는 제공된 회사 작성용 `.xlsx` 한 파일만 받습니다.
일반 회사 문서·도면·SDS·스캔본 업로드, 파일 유형 선택, 열 이름 수동 연결, 여러 파일 연습자료 내려받기는 제공하지 않습니다.
왼쪽 **‘도면·MSDS 첨부 안내’**에는 별지와 본문에서 도면·지도·SDS를 확인할 위치, 파일마다 담겨야 할 내용을 텍스트 표로 보여 줍니다. 실제 파일은 이 화면에 올리지 않고 담당자가 계획서 초안과 대조해 준비합니다.

- **가상 회사 연습**: ‘가상 회사 정보가 채워진 엑셀 내려받기’에서 실제 작성 양식에 가상 사실을 넣은 파일을 받습니다. 그대로 업로드해 서술형·시나리오·DOCX 초안 생성을 연습할 수 있습니다. 1군은 연습 범위이며 법적 대상 판정이나 실제 지도·현장 확인을 뜻하지 않습니다.
- **엑셀 작성**: 단답형은 ‘사업장 정보’ 값 열, 반복 목록은 각 시트에서 한 행에 한 대상씩 입력합니다. 예시는 회사 정보에서 제외합니다.
- **입력 확인·수정(②)**: 빠진 필수값, 잘못된 숫자·선택값·CAS 번호, 중복 번호와 누락된 식별정보를 파일명·시트·셀과 함께 한 표에서 안내합니다. 잘못된 셀은 자동 작성에서 제외합니다. 계산·법령·문서 검증은 별도로 유지합니다.
- **최신본 교체**: 파일명이 달라도 엑셀 전체를 새 입력으로 반영합니다. 이전에 올린 자료에서 값을 섞어 채우지 않으며, 삭제된 행·비운 칸도 반영합니다. 손상 파일과 다른 양식은 적용하지 않고 이전 반영본을 유지합니다. 화면에는 현재 반영한 파일명과 한국 시간 기준 반영 시각을 표시합니다.
- **이력 보존**: 기존 프로젝트 자료·이전 엑셀의 읽기 결과와 작성자료는 이력에 보존하고 원본 첨부파일을 삭제하지 않습니다.
- **서술형**: 엑셀의 책임자·주기·방법 등 회사가 입력한 사실만으로 초안을 작성합니다. 로컬 AI는 문장을 다듬으며, 근거 없는 내용은 `[확인 필요]`로 남깁니다.
- **시나리오 후보(③)**: 인식된 자료의 물질×설비 후보를 보여 주고, 지도에서 사업장 경계를 확인하면 주변 지역을 검색합니다. 검색된 보호대상은 확인 전 후보로 기록합니다. 설비별 사고유형·경계까지 거리·액위도 이 단계에서 확인해 반영합니다.
- **작성·내려받기(④)**: 작성 버튼과 짧은 진행 상태를 보여 줍니다. 서술형 작성 시 “완료 N/전체 M개 · 현재 작성 중인 항목 · 진행률”을 표시합니다. 회사 문서에 완성된 글이 있거나 근거가 없어 작성하지 않는 항목은 전체 수에서 제외합니다. AI는 필요한 서술형 문장에만 사용하며, 1군의 지역사회 소통·기관 공조·주민 보호·대피계획도 대상입니다. 담당자·연락기관·장소·경로는 회사 자료로 확인하고, 자료에 없는 내용은 `[확인 필요]`로 남깁니다.
- **자료 요청서**: 현재 저장된 작성요건 목록으로 1·2군 공통, 1군 전용 순으로 필요한 파일·항목을 나열합니다(HWP/PDF 다운로드).
  물질·농도·취급량 등으로 적용 조건이 달라지는 항목은 승인된 최신 규정 DB와 원자료를 확인한 뒤 확정합니다.
  암호화·구형 HWP가 열리지 않으면 한글에서 HWPX로 저장해 올려 주세요. PDF 다운로드에는 한글 TTF 글꼴이 필요하며 Windows의 맑은 고딕을 기본으로 찾고, 없으면 `CAP_PDF_FONT_PATH`를 설정합니다.
- **사고시나리오 결과**: 대상 설비는 규정수량(규정 제23조, 별표 2)으로, 사고유형은 물질의 독성 구분·폭발한계로 프로그램이 정하고,
  피해반경·장외거리·영향범위 안 보호대상·시설빈도·위험도와 공정안전보고서 별지 제19호의2를 계산합니다. 사람은 화면에서 시나리오를 고르지 않습니다.
  확인값은 **사업장 업무 ③ 시나리오 후보**에서 반영합니다. 화면에서 지도에 사업장 경계를 정합니다. 화면을 열면 회사 파일의 주소로 지도를 찾고
  그 자리의 필지 경계(브이월드 연속지적도)를 표시합니다. 옆 필지를 눌러 더하거나 다시 눌러 빼고, 담장과 다르면 직접 고쳐 그린 뒤(도면의 GeoJSON·꼭짓점
  CSV도 가능) **‘이 경계로 확인’**을 누르면 경계 저장 → 경계 기준 주변 지도 조회 → 거리 계산 → 시나리오 재계산이 이어서 됩니다.
  주변에서 찾은 시설은 확인 전 후보로 별지 제8호 작성자료에 기록합니다. 설비 좌표가 없는 경우 설비에서 경계까지의 거리는 자동으로 확정하지 않고 ③에서 확인한 값을 받습니다.
  배경은 브이월드 항공사진·지적선(키가 없으면 오픈스트리트맵과 직접 그리기)입니다. 주소 검색은 브이월드, 안 되면 카카오를 씁니다.
  로컬 AI는 선정 근거 문장 다듬기와 보호대상 분류 제안에만 쓰고, 숫자는 계산 엔진에서만 나옵니다(근거 없는 숫자는 `[확인 필요]`).
- **연습용 가상 회사 자료**: 자료 접수의 ‘가상 회사 정보가 채워진 엑셀 내려받기’에서 가상 회사의 단답형 사실을 채운 파일을 받습니다. ‘사고시나리오 검토’와 ‘주변 보호대상’ 시트는 없으며, 올린 뒤 ③에서 경계와 설비별 확인값을 검토합니다. 승인 규정 DB·실제 주소·도면·현장 확인이 필요한 부분은 보완으로 남으며 법정 제출용 최종 완성본으로 간주하지 않습니다.

규칙의 정확한 기준과 시험 순서는 [자료 중심 업무 공간 안내](docs/evidence_workspace.md)를 참고하세요.

## 사실 카탈로그와 칸 연결

- `data/stage2/cap_fact_catalog.json`: 회사 사실 하나가 한 줄입니다(id, 이름, 단위·형식, 종류, 출처 구분, 작성자료 키·열, 알아보는 머리글 표기,
  올릴 파일 종류, 1군/2군, 쓰이는 별지·칸). 여러 별지에 쓰이는 사실도 한 번만 둡니다. 전문가가 이 파일을 고치면 파일 읽기·사실 표·업로드 양식이 함께 바뀝니다.
  `engine/stage2/cap_fact_catalog.py`의 `validate()`와 `tests/test_cap_fact_catalog.py`가 고친 내용을 서식 정의·항목 점검과 대조합니다.
- `data/stage2/cap_docx_cells.json`: 사실(또는 그 사실로 계산한 값)이 규정서식의 어느 표·칸에 들어가는지 적은 연결표입니다.
  `engine/stage2/cap_catalog_docx.py`가 이 순서대로 별지 제1·3·4·5·6·9·10·11호를 채우고, 나머지 별지는 예전 렌더러(`cap_baseline_docx.py`)가 채웁니다.
  조립기에 문제가 생기면 예전 렌더러로 만듭니다. `tests/test_cap_catalog_docx.py`가 두 결과가 바이트 단위로 같은지 여러 사업장으로 비교합니다.

```text
  ├─ 사고시나리오 결과: ① 사업장 경계·지도(유일한 화면 입력) ② 주변 보호대상(엑셀에 지도 조회 후보 채워 내려받기, 별지 제8호) ③ 시나리오·피해반경·장외거리(별지 제12·13호)
  │                    ④ 시설빈도·위험도(별지 제14·15호) ⑤ 공정안전보고서 별지 제19호의2 — 모두 파일로 계산한 결과(읽기 전용)
  └─ 제출·이행 관리: ① 제출본 저장 → ② 제출서식 → ③ 이전 제출본과 비교 → ④ 이행점검(CAP)
      제출본 저장·비교는 두 문서 공용. CAP 별지 제2·31·32호와 자체점검은 해당 단계에서 연결합니다.
공정안전보고서 (공정안전보고서 대상일 때 표시 — 회사 파일로 채운 결과를 서식별로 보기)
  ├─ 한눈에 보기, 별지 제12~21호 서식별 현황(읽기 전용, 빈칸은 어느 파일에 무엇을 적을지)
  ├─ 별지 제19호의2 시나리오 및 피해예측 결과(‘사고시나리오 결과’에서 계산한 결과를 보여 줌)
  ├─ 서술형 항목(파일 사실로 쓴 초안) · 행정서식 별지 제1호·제9호 초안 내려받기 · 첨부 자료(도면·MSDS)
  └─ 점검·내보내기
사업장 판정하기: 사업장·물질 목록(엑셀·CSV)을 올려 대상 여부를 판정(최대보유량 계산용 시설 입력 칸이 이 화면에 남아 있음)
참고: 규정 DB 관리, 법령·근거 라이브러리
```

- 별지 제1호, 제3~7호, 제9~11호와 제16호의 비상대응 서술은 별도 작성 화면 없이 **사업장 업무에서 올린 파일로 채워집니다.** 틀린 값은 해당 파일을 고쳐 다시 올립니다.
- **공정안전보고서**도 같은 방식입니다. 동력기계 목록·배관 및 개스킷 명세·안전밸브 명세·인터록·소화/화재탐지 설비·내화구조·국소배기·방폭기기·
  전문가 명단·비상장비·비상연락·세안시설은 서식 표와 같은 열 이름의 표(한 줄에 하나)로, 사업개요(별지 제12호)·행정서식 값·조건부 서식의
  ‘적용여부: 해당 없음’과 근거·운영계획 글은 ‘항목 | 값’ 표로 올립니다. 화학사고예방관리계획서에서 이미 올린 사업장·물질·설비·감지기 사실은
  다시 묻지 않고 별지 제12·13·15·17호의5에 씁니다. 별지 제15호의 재질·용접효율·두께 등은 설비사양 파일의 열로 읽습니다.
  엑셀 업로드 양식에는 공정안전보고서 표마다 시트가 하나씩 들어갑니다.
- 별지 제8호(주변 보호대상)와 제12~15호·공정안전보고서 별지 제19호의2는 **사고시나리오 결과** 화면에서 확인합니다. 사업장 업무 ③에서
  경계를 확인하면 주변을 검색해 보호대상 후보를 기록하고 시나리오를 다시 계산합니다. 설비별 확인값도 ③에서 반영합니다.
- **판정**은 Stage 1 판정 엔진과 법령 최신성 확인을 씁니다. 화학사고예방관리계획서(1군·2군) 또는 공정안전보고서 대상일 때만
  프로젝트를 만들고, 승인 규정 DB가 없거나 법령이 최신이 아니면 판정을 보류합니다(fail-closed).
- 조건부 서식(공정안전보고서 제17호의2~20호)은 "적용/해당 없음"과 확인 근거를 먼저 받습니다.

## 자동으로 해 주는 일

‘사고시나리오 결과’ 화면의 지도는 브이월드 건물·하천·보호구역 윤곽을 표시하고, 담당자가 그린 사업장 경계로
내부·외부·경계 걸침을 구분해 경계 밖 500m 안의 이름 있는 시설과 거리를 조사표에 미리 채웁니다. 원래 도형·식별번호·출처는 보존합니다.
주소점이 든 필지 경계(브이월드 연속지적도)를 경계 초안으로 불러올 수 있습니다. 예전 시설 묶음 도구(`ui/surroundings_map_panel.py`)는
[주변 지도 조사 안내](docs/surroundings_map.md)와 예제에만 남아 있습니다.

## 계산의 근거

- **화학사고예방관리계획서**: 화학물질안전원 기술지침 제2021-3호(끝점 ERPG-2→AEGL-2→PAC-2→IDLH×0.1, 폭발 1 psi, 화재 5 kW/m²,
  기상 3 m/s D·최악 1.5 m/s F), KOSHA GUIDE P-92-2023(누출 식, 염소 예제로 검증), Briggs 가우시안 플룸, EPA RMP 증발·TNT 당량.
- **공정안전보고서 별지 제19호의2**: 서식 기본 끝점. 독성 ERPG 값은 KOSHA GUIDE C-C-46-2026 표1(국내 근거표)이며, 표에 없는 등급은 같은
  규정의 산정 규칙(예: ERPG-1 = ERPG-2/10)으로 계산하되 "추정"으로 표시하고, NA 등급은 생략합니다. 두 문서가 각자의 근거표를 쓰므로
  같은 물질도 값이 다를 수 있습니다.
- **기상**: 기상청 지상(ASOS) 일자료 지난 3년으로 대기온도(최고기온의 최댓값)와 습도(평균 상대습도)를 산정합니다.
- 근거 지침 목록과 판본은 `data/stage2/kosha_guides/registry.json`에서 관리하고, 새 판본이 나오면 "재검토 필요"로만 알립니다(값을 자동으로 바꾸지 않음).
  원문 PDF는 저장소에 넣지 않고 `data/runtime/kosha_guides/` 로컬 캐시에만 둡니다.

### CAP 제출유형·버전·행정서식

- CAP 작성자료는 제출 시점별 불변 스냅샷으로 저장할 수 있습니다. 신규제출은 `CAP-v1.0`, 변경제출은 `CAP-v1.1`, 재제출 계열은 `CAP-v2.0`처럼 관리합니다.
- 이전 제출본에서 현재 작업본을 복제해 변경된 부분만 수정하고, 필드 단위 변경점을 자동 비교할 수 있습니다.
- 별지 제31호(검토신청서)는 신규제출·재제출·5년 재제출·부적합 후 재제출·이행점검 부적정 재제출에 연결됩니다.
- 별지 제32호(변경 검토신청서)는 변경제출에 연결되며, 이전 버전과 현재본의 차이를 이용해 뒤쪽의 유해화학물질 추가·시설 추가·취급저장량 증가 표를 자동 작성합니다.
- 자동 비교에서 만든 별지 제2호 변경내역 관리대장 행은 **후보**로 제시되며 담당자가 변경종류·후속조치·문구를 확인한 뒤 저장합니다.
- 별지 제31호·32호는 사용자가 제공한 「화학물질관리법 시행규칙」 2025.8.7 개정 HWP 원본을 출처 근거로, 함께 제공된 PDF를 시각적 레이아웃 기준으로 사용합니다. 원본 파일의 SHA-256은 `data/templates/cap/cap_submission_forms_sources.json`에 기록합니다.

### 법령 개정 반영(작성본 최신화)

- 버전을 저장할 때 그 시점의 승인된 법령판(법령별 일련번호·시행일·공포정보, 별표·별지 첨부별 해시)과 규칙 판정 결과(별지 제1호 규정수량 비교, 작성수준)를 함께 기록합니다.
- **프로젝트를 열면** 작성 화면과 제출·이행 관리 화면 상단에 최근 버전 이후 개정된 법령 수와 다시 작성·확인할 칸 수를 알려 줍니다. 최신화 작업본을 만든 뒤에는 아직 다시 확정하지 않은 칸 목록을 보여 줍니다.
- 제출·이행 관리 → 이전 제출본과 비교의 **개정 법령 점검**에서 개정 법령별 바뀐 점(시행일·공포번호, 바뀐 별표·별지 이름)과 영향 서식을 보여 주고, **개정 전후 조문 보기**로 법제처 신구법 비교 API(법령 `oldAndNew`, 행정규칙 `admrulOldAndNew`)의 신구조문을 불러옵니다(누를 때만 조회, `data/runtime/law_old_new/` 캐시). 법제처 비교는 현재 판과 바로 직전 판 사이이므로 여러 번 개정되었다면 마지막 개정만 보입니다.
- 영향받는 칸은 두 가지로 나눕니다. **다시 작성 필요**: 별지 서식을 담은 법령(작성규정·시행규칙·이행규정·PSM 고시)의 첨부원본이 바뀐 경우. **내용 확인**: 조문·작성방법만 바뀐 경우.
- 규정수량 개정은 현재 판정표로 별지 제1호를 다시 계산해 이전 결과와 비교하고, 비교 결과가 달라지면 작성수준 재판정을 요청합니다.
- **최신화 작업본 만들기**를 누르면 기준 버전을 작업본으로 복제하고 영향 칸을 `[법령 개정 재작성]` 또는 `[법령 개정 재확인]`(HOLD)으로 돌립니다. 값은 지우지 않으며 담당자가 다시 확정해야 완료됩니다. 별지 제2호 '정보 현행화' 행은 후보로만 보여 줍니다.
- 법령판 기록이 없는 옛 버전은 버전 저장 이후 시행된 개정으로 판단합니다. 법령→별지·칸 연결은 `data/stage2/legal_impact_map.json`에서 관리합니다(초안, 전문가 검토로 범위 조정). 신구법 API 응답 구조는 실제 인증키로 아직 검증하지 못했습니다. 서술형 문장의 AI 수정안은 아직 만들지 않습니다.

### CAP 이행점검·자체점검

- 적합·제출 당시 CAP 버전을 기준으로 이행규정 별지 제2호의 77개 확인항목을 자체점검할 수 있습니다.
- 각 항목은 `확인 / 개선필요 / 해당없음 / 미확인`으로 관리하며, 미확인 항목은 완료 처리하지 않습니다.
- `개선필요` 항목은 이행규정 별지 제3호 개선사항 조치 내역으로 자동 연결되고, 조치결과·조치일자·책임부서·확인자가 확인될 때까지 완료되지 않습니다.
- 이행규정 별지 제1호 자체점검 결과서는 기존 사업장 정보와 자체점검 기간·점검반 정보를 재사용해 작성합니다.
- 1군(주요취급시설)은 자체점검 별지 1~3호와 함께 기존 작성규정 별지 제2호 변경내역 관리대장을 제출 패키지에 포함합니다. 변경사항이 없는 경우에도 회사가 확인한 빈 관리대장을 허용합니다.
- 자체점검 법정 항목 출처는 `data/templates/cap/cap_implementation_forms_sources.json`, 구조화된 체크리스트는 `data/stage2/cap_implementation_self_check.json`에 기록합니다.

### 알려진 한계 (전문가 검토 필요)

- 공정안전보고서 본문 별지 제12~21호 15종은 규정서식 baseline에 포함되어 있습니다. 별지 제1호 심사신청서와 별지 제9호 확인요청서는 현행 규정에서 확인된 항목 구조를 바탕으로 DOCX 작성지원본을 생성하며, 원본 HWP/DOCX의 바이너리·서식 배치를 그대로 복제했다고 간주하지 않습니다. 제출 전 국가법령정보센터 원문 및 실제 제출기관 안내와 최종 대조합니다.
- 밀도가 높은 가스 효과, BLEVE·TNO 다중에너지, 2상 비평형 방출은 모델에 넣지 않았습니다. 지형·풍향은 원형(보수적)으로 계산합니다.
- 별지 제19호의2의 폭발 21·70 kPa와 인화성 확산(25% LEL·LEL·UEL) 거리는 근거 자료가 확인되지 않아 계산하지 않고 비워 둡니다.
- 관측소는 주소에 지점 이름이 있을 때만 자동 선택하고, 없으면 목록에서 고릅니다. 습도는 서식의 "낮 동안 평균"이 아니라 하루 평균입니다.
- AI 초안은 실제 로컬 모델로 품질을 검증하지 못했습니다(가짜 응답으로 생성·검증·승인 흐름만 테스트). 예시 문장과 설명문은 전문가 검토가 필요한 초안입니다.
- 카카오·KOSHA·코샤가이드·기상청 API는 실제 키로 호출해 검증하지 못했습니다.
- 보고서 서술 장은 한 항목이 칸 여러 개를 채울 때 "본문에 함께 기술함" 문구가 칸 수만큼 반복됩니다.
- 사고시나리오 결과는 풍향·지형을 반영하지 않은 원형 범위의 자체 계산이라 KORA 등 동등 프로그램 결과와 대조해 확정해야 합니다.
  설비에서 사업장 경계까지 거리는 아직 지도에서 재지 않고 검토자료 파일의 ‘경계까지 거리(m)’를 씁니다(설비 위치를 지도에 찍는 기능 없음).
- 브이월드 연속지적도(LP_PA_CBND_BUBUN) 필지 조회, 항공사진·지적선 배경(WMTS·WMS)은 실제 키로 호출해 검증하지 못했습니다(가짜 응답으로만 시험).
  필지를 못 찾으면 ‘직접 그리기·고치기’로 그리면 됩니다. 배경 타일 주소에는 브이월드 키가 들어가므로, 키를 발급할 때 프로그램을 띄우는 도메인을 등록해 두세요.
- 예전 화면에서 사람이 확정해 둔 시나리오 목록이 있는 사업장도 ‘사고시나리오 결과’를 열면 파일·규정수량 기준 목록으로 다시 계산됩니다.
- 사실 카탈로그의 머리글 표기와 칸 연결표는 초안입니다. 실제 회사 파일 표기로 넓히려면 전문가 검토가 필요합니다.
- ‘사업장 판정하기’의 시설 입력 칸은 아직 화면에서 직접 입력하는 방식입니다.

## 내보내기와 검증

점검·내보내기는 두 문서가 같은 화면 부품(`ui/report_export_panel.py`)을 씁니다.

- 자료를 점검해 보완 필요·담당자 확인 필요·확인 완료를 나누고, 도면·MSDS 같은 첨부는 "최종 제출 전 별도 준비"로 분리합니다.
- 결과물은 언제나 **초안**입니다(`…_규정서식_초안.docx`, `…_내부_초안.docx`). 내려받기 전에 확인 단계는 없으며,
  내부 초안 끝의 ‘프로그램 보완 안내’에 남은 일(빈 사실·충돌·승인 DB 등)이 정리됩니다.
- 규정서식 초안 DOCX, 내부 초안 DOCX, 출력물 검증정보(JSON, SHA-256), 검증 묶음 ZIP을 내려받습니다.
- 화학사고예방관리계획서는 최종 제출 확인(타 제도 심사결과 활용·공동제출 증빙)과 최종 체크포인트도 함께 판정합니다.
- 올린 파일(도면·MSDS·증빙)은 SHA-256과 함께 기록하며, 올렸다고 내용을 확인한 것으로 보지 않습니다(담당자 확인 전 HOLD).

DOCX가 만들어져도 제출 확정본으로 간주하지 않습니다. 제출 전에 담당자가 사실·수치·도면·MSDS를 최종 대조해야 합니다.

## 작성자료 상태

`Stage2Project.fields`에 사실을 저장하고 각 값에 상태를 붙입니다.

- `VERIFIED` 근거와 함께 확인됨 / `USER_CONFIRMED` 담당자 확인 / `FILE_READ` 회사 파일에서 읽어 자동 반영(사람이 확인한 값 아님) / `CALCULATED` 계산 산출
- `AI_DRAFT` 사람 검토 전 초안 / `HOLD` 미확인
- 서식에는 `VERIFIED`·`USER_CONFIRMED`·`FILE_READ`·`CALCULATED`를 씁니다. 파일에서 읽은 값은 예전에는 `USER_CONFIRMED`로 저장했지만,
  사람이 확인하지 않았으므로 `FILE_READ`로 구분합니다(메모가 ‘공통정보 연결’로 시작). 새 파일을 올리면 이 값들은 잠시 `HOLD`가 되었다가 다시 반영됩니다.

저장 위치는 `data/runtime/stage2/projects/<project_id>/`이며 회사 자료는 Git에 올리지 않습니다.

## API 설정

```text
LAW_OC=국가법령정보_공동활용_인증값
KOSHA_MSDS_SERVICE_KEY=공공데이터포털_인증키   # KOSHA MSDS, 코샤가이드, 기상청 ASOS 일자료 조회에 공용
KAKAO_REST_API_KEY=카카오_REST_API_키          # 주소 좌표·주변 보호대상 조회(선택)
```

키가 없으면 해당 조회는 하지 않고 직접 입력으로 넘어갑니다. AI 초안은 이 PC의 로컬 AI(Ollama 등)만 사용하며 회사 정보를 외부로 보내지 않습니다.

```bash
pip install -r requirements.txt
streamlit run app.py
python -m pytest -q
```

PR과 `main` push에서 CI가 전체 테스트를 실행합니다.
