# 화학안전 계획서 작성지원 (planner)

**화학사고예방관리계획서**(화학물질관리법 시행규칙 별지 제1~16호)와 **공정안전보고서**(산업안전보건법, 고용노동부고시 별지 제12~21호)를
사람이 최소한만 입력해서 작성하도록 돕는 Streamlit 프로그램입니다. 사업장 정보를 한 번만 적으면 두 문서가 그 값을 나눠 쓰고,
계산·조회로 나오는 값은 자동으로 채우며, 마지막에 규정서식 DOCX를 내려받습니다.

## 만든 철학

1. **사람은 프로그램이 알 수 없는 것만 입력합니다.** 계산·조회·규정에서 나오는 값은 자동으로 채웁니다.
2. **한 번 입력한 사실은 다시 묻지 않습니다.** 시설·물질·시나리오는 두 문서가 공유하고, 기상값은 주소로 자동 산정합니다.
3. **신입사원도 쓸 수 있게** 칸마다 쉬운 설명, 예시 고르기, 문장 틀을 붙입니다.
4. **법령 우선**: 자료가 서로 다르면 `시행규칙·고시 > 화학물질안전원·KOSHA 기술지침 > 작성 매뉴얼 > 기존 프로그램(KORA)` 순으로 따릅니다.
5. **AI는 글만 씁니다.** 법적 대상 판정과 숫자 계산은 규칙 엔진이 하고, AI 초안은 담당자가 확인·승인하기 전에는 완료로 보지 않습니다.
6. **근거 없는 값은 채우지 않습니다.** 확인되지 않은 칸은 빈칸 또는 `[확인 필요]`로 남기고 이유를 알려 줍니다.

## 사용 흐름

기본 시작 화면은 **사업장 업무**입니다. 서식을 채우는 대신 회사 자료(CSV·XLSX·DOCX·HWPX·텍스트 PDF)를 올리면
규칙이 출처와 함께 값을 먼저 채우고, 사람은 **충돌·값 오류·신뢰도 부족** 같은 예외만 처리합니다.
물질·설비 파일을 한 번에 선택하면 머리글로 종류를 분류하고, 모호한 파일만 종류를 확인합니다.
- **자동 기입**: 충돌·범위·단위·CAS 검산·추출 경로를 통과한 표의 값. 법적 판단에 쓰이는 값과 순위를 바꾸는 핵심값은 더 높은 출처 신뢰도를 요구합니다.
- **시나리오 후보**: 확인 전 값도 ‘잠정’으로 써서 자료를 올린 직후부터 물질×설비 순위를 보여 주고, 순위를 바꾸는 빈 값만 먼저 묻습니다. 같은 물질·설비를 공유하는 조합은 함께 민감도를 검사하고, 출처·가정·남은 확인 작업을 조합별 검토 초안으로 내려받을 수 있습니다.
- 법적 계산에 쓰이는 자동 기입값은 담당자가 원자료를 확인해야 기존 작성자료에 연결됩니다. 선택한 로컬 LLM은 원문 인용이 확인되는 값만 후보로 제안하며 자동 확정하지 않습니다.

규칙의 정확한 기준과 시험 순서는 [자료 중심 업무 공간 안내](docs/evidence_workspace.md)를 참고하세요.

```text
사업장 업무 (기본 화면): 전체 준비자료 요청서(HWP/PDF) → 자료 한 번에 접수 → 파일별 수정 요청 → 시나리오 후보 → 작성자료 연결

자료 요청서는 현재 저장된 작성요건 목록을 바탕으로 1·2군 공통, 1군 전용 순으로 나열합니다. 2군 전용 항목이 없으므로 빈 구역은 표시하지 않습니다. 직접 확인된 별지 번호만 구역에 표기하고, 나머지는 공통자료·별지 번호 없는 작성자료로 분류합니다. 물질·농도·취급량 등으로 적용 조건이 달라지는 항목은 승인된 최신 규정 DB와 원자료를 확인한 뒤 확정해야 합니다. HWP 5.0 바이너리와 HWPX를 직접 읽습니다. 암호화·구형 HWP가 열리지 않으면 한글에서 HWPX로 저장한 뒤 올려 주세요. PDF 다운로드에는 한글 TTF 글꼴이 필요하며 Windows의 맑은 고딕을 기본으로 찾고, 없으면 `CAP_PDF_FONT_PATH`를 설정합니다.

화면의 연습용 가상 회사 자료는 하나의 큰 ZIP입니다. 기존 7개 자료와 중복 설비번호·혼합물 성분·개정 충돌을 담은 추가 5개 자료, 통합 정답표를 한 묶음에 넣었습니다. 실제 주소 입력·작은 자료·별도 압박 시험·고급 AI 메뉴는 이 화면에서 제거했습니다. 이 ZIP만 올려 법정 서식 전체를 자동 완성할 수 있다고 간주하지 않습니다.

`synthetic_company_full_plan.zip`에는 동일한 자료의 XLSX/DOCX판과 HWPX/HWP 5.0판을 함께 넣었습니다(형식 비교용 복제본이므로 한 프로젝트에는 한 형식만 올림). 일반정보·공정·안전관리 문서는 업로드해도 서식 필드에 자동 연결되지 않는 부분이 있으며, 접수 화면에서 원본 보관과 보완 요청으로 표시합니다. 이 자료만 올려 화학사고예방관리계획서를 끝까지 자동 완성했다는 뜻은 아닙니다. 도면 이외의 미연결 필드도 남습니다.
  (새 사업장은 여기서만 만듭니다. 아래 작성 화면은 이미 있는 사업장을 이어서 작성합니다)
  └─ 버전 관리: 제출 시점 저장·변경점 비교·이전 제출본에서 시작·법령 개정 반영 (화학사고예방관리계획서·공정안전보고서 공용)
화학사고예방관리계획서 (하는 일별 화면 5개, 모두 사업장 업무에서 만든 사업장을 골라 이어서 작성)
  ├─ 사업장·물질·시설 작성: 별지 제1호, 제3~11호
  ├─ 사고시나리오·위험도: 별지 제12·13호, 제14호, 제15호
  ├─ 비상대응·서술형: 별지 제16호, 사전관리방침, 내부·외부 비상대응계획 (외부는 1군만)
  ├─ 점검·내보내기: 최종 제출 확인, 첨부 자료, 점검, DOCX
  └─ 제출·변경·이행점검: 별지 제2호 변경내역 관리대장, 별지 제31·32호, 이행점검 자체점검 (버전을 비교 기준으로 사용)
공정안전보고서 작성 (공정안전보고서 대상일 때 표시)
  ├─ 별지 제12·13·14·15·16·17·17호의2~5·18·19·19호의2·20·21호
  ├─ 제출·확인 행정서식: 별지 제1호 심사신청서 / 별지 제9호 확인요청서
  ├─ 서술형 항목 · 첨부 자료(도면·MSDS)
  └─ 점검·내보내기
사업장 판정하기: 사업장·물질 목록(엑셀·CSV 업로드 가능)을 넣고 질문에 답해 판정한 뒤 작성으로 이동
참고: 규정 DB 관리, 법령·근거 라이브러리
```

- **시작하기**는 Stage 1 판정 엔진과 법령 최신성 확인을 그대로 씁니다. 화학사고예방관리계획서(1군·2군) 또는 공정안전보고서 대상일 때만
  프로젝트를 만들고, 승인 규정 DB가 없거나 법령이 최신이 아니면 판정을 보류합니다(fail-closed).
- 조건부 서식(공정안전보고서 제17호의2~20호)은 "적용/해당 없음"과 확인 근거를 먼저 받습니다.

## 자동으로 해 주는 일

별지 제8호의 **주소 조사·지도 정리**에서는 건물 윤곽을 지도에 표시하고, 담당자가 그린 사업장 경계로
내부·외부·경계 걸침을 구분합니다. 시설 묶음을 확인해 미검토 목록으로 연결하며 원래 도형·식별번호·출처는 보존합니다.
사용 순서와 가상 예제는 [주변 지도 조사 안내](docs/surroundings_map.md)를 참고하세요.

## 계산의 근거

- **화학사고예방관리계획서**: 화학물질안전원 기술지침 제2021-3호(끝점 ERPG-2→AEGL-2→PAC-2→IDLH×0.1, 폭발 1 psi, 화재 5 kW/m²,
  기상 3 m/s D·최악 1.5 m/s F), KOSHA GUIDE P-92-2023(누출 식, 염소 예제로 검증), Briggs 가우시안 플룸, EPA RMP 증발·TNT 당량.
- **공정안전보고서 별지 제19호의2**: 서식 기본 끝점. 독성 ERPG 값은 KOSHA GUIDE C-C-46-2026 표1(국내 근거표)이며, 표에 없는 등급은 같은
  규정의 산정 규칙(예: ERPG-1 = ERPG-2/10)으로 계산하되 "추정"으로 표시하고, NA 등급은 생략합니다. 두 문서가 각자의 근거표를 쓰므로
  같은 물질도 값이 다를 수 있습니다.
- **기상**: 기상청 지상(ASOS) 일자료 지난 3년으로 대기온도(최고기온의 최댓값)와 습도(평균 상대습도)를 산정합니다.
- 근거 지침 목록과 판본은 `data/stage2/kosha_guides/registry.json`에서 관리하고, 새 판본이 나오면 "재검토 필요"로만 알립니다(값을 자동으로 바꾸지 않음).
  원문 PDF는 저장소에 넣지 않고 `data/runtime/kosha_guides/` 로컬 캐시에만 둡니다.

### CAP 제출유형·버전·행정서식

- CAP 작성자료는 제출 시점별 불변 스냅샷으로 저장할 수 있습니다. 신규제출은 `CAP-v1.0`, 변경제출은 `CAP-v1.1`, 재제출 계열은 `CAP-v2.0`처럼 관리합니다.
- 이전 제출본에서 현재 작업본을 복제해 변경된 부분만 수정하고, 필드 단위 변경점을 자동 비교할 수 있습니다.
- 별지 제31호(검토신청서)는 신규제출·재제출·5년 재제출·부적합 후 재제출·이행점검 부적정 재제출에 연결됩니다.
- 별지 제32호(변경 검토신청서)는 변경제출에 연결되며, 이전 버전과 현재본의 차이를 이용해 뒤쪽의 유해화학물질 추가·시설 추가·취급저장량 증가 표를 자동 작성합니다.
- 자동 비교에서 만든 별지 제2호 변경내역 관리대장 행은 **후보**로 제시되며 담당자가 변경종류·후속조치·문구를 확인한 뒤 저장합니다.
- 별지 제31호·32호는 사용자가 제공한 「화학물질관리법 시행규칙」 2025.8.7 개정 HWP 원본을 출처 근거로, 함께 제공된 PDF를 시각적 레이아웃 기준으로 사용합니다. 원본 파일의 SHA-256은 `data/templates/cap/cap_submission_forms_sources.json`에 기록합니다.

### 법령 개정 반영(작성본 최신화)

- 버전을 저장할 때 그 시점의 승인된 법령판(법령별 일련번호·시행일·공포정보, 별표·별지 첨부별 해시)과 규칙 판정 결과(별지 제1호 규정수량 비교, 작성수준)를 함께 기록합니다.
- **프로젝트를 열면** 작성 화면과 버전 관리 화면 상단에 최근 버전 이후 개정된 법령 수와 다시 작성·확인할 칸 수를 알려 줍니다. 최신화 작업본을 만든 뒤에는 아직 다시 확정하지 않은 칸 목록을 보여 줍니다.
- 버전 관리의 **개정 법령 점검**에서 개정 법령별 바뀐 점(시행일·공포번호, 바뀐 별표·별지 이름)과 영향 서식을 보여 주고, **개정 전후 조문 보기**로 법제처 신구법 비교 API(법령 `oldAndNew`, 행정규칙 `admrulOldAndNew`)의 신구조문을 불러옵니다(누를 때만 조회, `data/runtime/law_old_new/` 캐시). 법제처 비교는 현재 판과 바로 직전 판 사이이므로 여러 번 개정되었다면 마지막 개정만 보입니다.
- 영향받는 칸은 두 가지로 나눕니다. **다시 작성 필요**: 별지 서식을 담은 법령(작성규정·시행규칙·이행규정·PSM 고시)의 첨부원본이 바뀐 경우. **내용 확인**: 조문·작성방법만 바뀐 경우.
- 규정수량 개정은 현재 판정표로 별지 제1호를 다시 계산해 이전 결과와 비교하고, 비교 결과가 달라지면 작성수준 재판정을 요청합니다.
- **최신화 작업본 만들기**를 누르면 기준 버전을 작업본으로 복제하고 영향 칸을 `[법령 개정 재작성]` 또는 `[법령 개정 재확인]`(HOLD)으로 돌립니다. 값은 지우지 않으며 담당자가 다시 확정해야 완료됩니다. 별지 제2호 '정보 현행화' 행은 후보로만 보여 줍니다.
- 법령판 기록이 없는 옛 버전은 버전 저장 이후 시행된 개정으로 판단합니다. 법령→별지·칸 연결은 `data/stage2/legal_impact_map.json`에서 관리합니다(초안, 전문가 검토로 범위 조정). 신구법 API 응답 구조는 실제 인증키로 아직 검증하지 못했습니다. 서술형 문장의 AI 수정안은 아직 만들지 않습니다.

### CAP 이행점검·자체점검

- 적합·제출 당시 CAP 버전을 기준으로 이행규정 별지 제2호의 77개 확인항목을 자체점검할 수 있습니다.
- 각 항목은 `확인 / 개선필요 / 해당없음 / 미확인`으로 관리하며, 미확인 항목은 완료 처리하지 않습니다.
- `개선필요` 항목은 이행규정 별지 제3호 개선사항 조치 내역으로 자동 연결되고, 조치결과·조치일자·책임부서·확인자가 확인될 때까지 완료되지 않습니다.
- 이행규정 별지 제1호 자체점검 결과서는 기존 사업장 정보와 자체점검 기간·점검반 정보를 재사용해 작성합니다.
- 1군(주요취급시설)은 자체점검 별지 1~3호와 함께 기존 작성규정 별지 제2호 변경내역 관리대장을 제출 패키지에 포함합니다. 변경사항이 없는 경우에도 회사가 확인한 빈 관리대장을 허용합니다.
- 자체점검 법정 항목 출처는 `data/templates/cap/cap_implementation_forms_sources.json`, 구조화된 체크리스트는 `data/stage2/cap_implementation_self_check.json`에 기록합니다.

### 알려진 한계 (전문가 검토 필요)

- 공정안전보고서 본문 별지 제12~21호 15종은 규정서식 baseline에 포함되어 있습니다. 별지 제1호 심사신청서와 별지 제9호 확인요청서는 현행 규정에서 확인된 항목 구조를 바탕으로 DOCX 작성지원본을 생성하며, 원본 HWP/DOCX의 바이너리·서식 배치를 그대로 복제했다고 간주하지 않습니다. 제출 전 국가법령정보센터 원문 및 실제 제출기관 안내와 최종 대조합니다.
- 밀도가 높은 가스 효과, BLEVE·TNO 다중에너지, 2상 비평형 방출은 모델에 넣지 않았습니다. 지형·풍향은 원형(보수적)으로 계산합니다.
- 별지 제19호의2의 폭발 21·70 kPa와 인화성 확산(25% LEL·LEL·UEL) 거리는 근거 자료가 확인되지 않아 계산하지 않고 비워 둡니다.
- 관측소는 주소에 지점 이름이 있을 때만 자동 선택하고, 없으면 목록에서 고릅니다. 습도는 서식의 "낮 동안 평균"이 아니라 하루 평균입니다.
- AI 초안은 실제 로컬 모델로 품질을 검증하지 못했습니다(가짜 응답으로 생성·검증·승인 흐름만 테스트). 예시 문장과 설명문은 전문가 검토가 필요한 초안입니다.
- 카카오·KOSHA·코샤가이드·기상청 API는 실제 키로 호출해 검증하지 못했습니다.
- 보고서 서술 장은 한 항목이 칸 여러 개를 채울 때 "본문에 함께 기술함" 문구가 칸 수만큼 반복됩니다.

## 내보내기와 검증

점검·내보내기는 두 문서가 같은 화면 부품(`ui/report_export_panel.py`)을 씁니다.

- 자료를 점검해 보완 필요·담당자 확인 필요·확인 완료를 나누고, 도면·MSDS 같은 첨부는 "최종 제출 전 별도 준비"로 분리합니다.
- 남은 항목이 없으면 "작성자료 확인 완료", 남아 있어도 현재 자료로 "검토용 초안"을 만들 수 있습니다.
- **작성본 표시는 문서별 최종 준비 기준을 통과할 때만** 붙습니다. 통과하지 못하면 파일명·검증정보 모두 "검토용"입니다.
- 규정서식 DOCX, 내부 검토용 DOCX, 출력물 검증정보(JSON, SHA-256), 검증 묶음 ZIP을 내려받습니다.
- 화학사고예방관리계획서는 최종 제출 확인(타 제도 심사결과 활용·공동제출 증빙)과 최종 체크포인트도 함께 판정합니다.
- 올린 파일(도면·MSDS·증빙)은 SHA-256과 함께 기록하며, 올렸다고 내용을 확인한 것으로 보지 않습니다(담당자 확인 전 HOLD).

DOCX가 만들어져도 제출 확정본으로 간주하지 않습니다. 제출 전에 담당자가 사실·수치·도면·MSDS를 최종 대조해야 합니다.

## 작성자료 상태

`Stage2Project.fields`에 사실을 저장하고 각 값에 상태를 붙입니다.

- `VERIFIED` 근거와 함께 확인됨 / `USER_CONFIRMED` 담당자 확인 / `CALCULATED` 계산 산출
- `AI_DRAFT` 사람 검토 전 초안 / `HOLD` 미확인

저장 위치는 `data/runtime/stage2/projects/<project_id>/`이며 회사 자료는 Git에 올리지 않습니다.

## API 설정

프로젝트 루트 `.env`에 입력합니다(GitHub에 올리지 마세요).

```text
LAW_OC=국가법령정보_공동활용_인증값
KOSHA_MSDS_SERVICE_KEY=공공데이터포털_인증키   # KOSHA MSDS, 코샤가이드, 기상청 ASOS 일자료 조회에 공용
KAKAO_REST_API_KEY=카카오_REST_API_키          # 주소 좌표·주변 보호대상 조회(선택)
```

키가 없으면 해당 조회는 하지 않고 직접 입력으로 넘어갑니다. AI 초안은 이 PC의 로컬 AI(Ollama 등)만 사용하며 회사 정보를 외부로 보내지 않습니다.

## 실행과 테스트

실제 주소로 카카오·브이월드·국토정보플랫폼 연결을 시험하려면 `python check_address_apis.py`를 실행합니다.
브이월드는 키 외에 발급 시 등록한 `VWORLD_DOMAIN`을 `.env`에 설정합니다.
레이어별 원자료 건수와 필터 제외 건수, 조회 오류를 확인하는 방법은
[주소 API 시험 안내](docs/address_api_smoke_test.md)를 참고하세요.

```bash
pip install -r requirements.txt
streamlit run app.py
python -m pytest -q
```

PR과 `main` push에서 CI가 전체 테스트를 실행합니다.
