# 자료 중심 업무 공간

프로그램의 시작 화면은 ‘사업장 업무’입니다. 서식 칸을 채우는 대신 **회사 자료를 올리면 초안이 먼저 만들어지고,
사람은 프로그램이 알려 주는 파일을 고쳐 다시 올립니다.** 화면 안에 승인·확인 절차는 없고, 결과물은 늘 초안입니다.
기존 별지 작성·법적 대상 판정·계산 엔진은 유지합니다.

## 사용 순서

화면은 네 단계입니다. 신입사원이 화학사고예방관리계획서를 몰라도 따라올 수 있도록 사람 말로만 안내하고,
파일 지문(SHA256)·내부 식별자·JSON은 ④의 ‘검토·감사용 기록’에만 둡니다.

1. **① 자료 올리기**: 회사 파일을 한 번에 올립니다. 파일(시트)마다 종류를 알아봅니다.
   - 설비(설비번호·구분기호 열), 물질(제품코드 열, 없으면 항목명), 가스감지기(감지기 번호 열), 사업장 정보·공정 설명·비상대응계획(‘항목 | 값’ 표나 ‘대표자: 홍길동’ 줄)
   - 시트마다 종류가 분명한 묶음 엑셀은 ‘여러 종류가 든 묶음 파일’로 보고 시트별로 읽습니다. 설비-제품 대응표처럼 한 표에 두 식별자가 있으면 묻습니다.
   - 머리글 표기는 기본 항목(설비·물질의 법적 계산값)과 **사실 카탈로그**(`data/stage2/cap_fact_catalog.json`)의 headers로 알아봅니다.
   - 파일마다 **읽기 결과**(머리글로 본 줄, 쓴 열·못 쓴 열, 건너뛴 줄과 이유, 그대로 쓸 수 없는 칸)를 보여 줍니다.
     못 쓴 열은 무엇인지 한 번 고르면 같은 이름의 열을 모두 그렇게 읽고 다시 읽습니다. 잘못 올린 파일은 ‘이 파일 빼기’로 뺍니다.
   - **같은 이름으로 다시 올리면** 예전 파일과 그 값을 새 파일로 바꿉니다(고친 파일을 다시 올리는 경우).
   - 읽은 직후 “O가 N개 늘었고 새 충돌 M개”처럼 사실 표의 변화를 알려 줍니다.
2. **② 파일별 보완 요청**: 
   - **올린 파일을 어디까지 읽었나요**: 파일별 읽음/일부만 읽음/읽지 못함과 이유·고치는 방법.
   - **화학사고예방관리계획서에 필요한 사실**: 사실 카탈로그 한 줄에 사실 하나. `O`(파일에서 찾음, 출처 파일·위치), 빈칸(어느 파일에 어떤 항목 이름으로 적을지),
     `⚠ 충돌`(파일끼리 또는 이미 저장된 값과 다름 — 초안에 넣지 않음), `△ 확인`(단위 없음·형식 오류 등). ‘쓰이는 곳’, 1군/2군·별지 필터,
     설비×항목·물질×항목·감지기×항목 표. 계산값·법령 조회값·지도 조사값은 따로 ‘계산됨/계산 전’으로 보여 줍니다.
   - **엑셀 업로드 양식**: 빈 사실만 열로 넣은 엑셀을 받아 채워 올리면 다른 파일과 똑같이 읽힙니다(열 이름은 읽기 코드가 알아보는 표기).
   - **파일별 수정 요청**: 파일·위치·항목·문제·수정 요청을 한 줄씩 적은 표(TXT로 내려받아 회사에 보냄). 같은 표기·같은 열은 한 줄로 모읍니다.
   - 예전의 ‘직접 확인·입력’(충돌 값 고르기, 값 대신 적기, 표기·단위 답하기) 칸은 없앴습니다. 파일을 고치거나 업로드 양식을 채워 올립니다.
3. **③ 시나리오 후보**: 확인 전 값도 써서 **자료를 올린 직후부터** 물질×설비 검토 순서를 보여 줍니다.
   조합마다 어떤 값을 썼는지(채운 값 / 확인 전 / 임시값), 출처와 가정의 이유, 다음 할 일을 보여 줍니다.
   검토 초안(Markdown)을 내려받으면 모든 조합의 사용값·원문 위치·가정·남은 조사 항목을 한데 볼 수 있습니다.
   누출 위치·사고 유형·차단·주변 토지 이용 및 피해 계산은 아직 별도 검토가 필요합니다.
4. **④ 보내기·진행 현황**: 파일에서 읽어 정해진 값은 화면을 열 때 자동으로 작성자료로 보내집니다(상태 `FILE_READ`).
   물질·설비 표(`inventory.*`), 사업장 일반정보(`cap.business.*`), 공정 설명(`process.description`, `cap.basic.*`), 설비 사양(별지 제9호),
   확산방지설비(제10호), 가스감지기(제11호), 대표물질 유해성(제7호), 비상대응 서술(제16호)과 서술형 결정사항(`cap.facts.*`)이 대상입니다.
   사람이 다른 곳에서 적은 한 값은 덮어쓰지 않고 사실 표에 충돌로 알립니다.
   **서술형 항목**은 회사 파일의 사실만으로 초안을 만들고(근거 없으면 `[확인 필요]`), 로컬 AI로 문장을 다듬을 수 있습니다.
   이어서 **진행 현황판**이 문서별로 남은 일을 보여 줍니다.

## 자동 기입 규칙

자동 기입은 다음을 **모두** 통과해야 합니다. 모델이 자신의 확신도를 말해도 승인 근거가 되지 않습니다.

| 검사 | 통과 조건 |
|---|---|
| 충돌 | 같은 대상·항목의 모든 출처 값이 같음 (같으면 오히려 교차 확인된 값) |
| 유효성 | 숫자 항목은 숫자, 허용 범위 안, CAS는 형식·검산, 선택형은 허용 값 |
| 단위 | 항목명에 단위가 있음 (`운전압력` ✗ / `운전압력(MPa)` ✓) |
| 추출 경로 | 표에서 읽음. 문장·로컬 AI·수동 후보는 자동 기입하지 않음 |
| 출처 신뢰도 | 아래 표 |

신뢰도는 *검토 우선순위*이며 실제 정확도나 법적 증명력이 아닙니다.

| 출처 | 신뢰도 |
|---|---|
| 설비번호·제품코드가 있는 표 | 0.98 |
| 수식 계산 결과 / 병합 셀에서 가져온 값 | 0.90 |
| 직접 표시된 `항목: 값` 문장 | 0.88 |
| 이름만으로 연결한 표 | 0.78 |
| 로컬 LLM 제안 | 0.55 |

**영향에 따라 문턱이 달라집니다.** 법적 판단에 쓰이는 항목(최대보유량·함량·CAS·용량·시설유형·성상·비중·공정유형)과
‘순위를 바꾸는 핵심값’은 0.98이 필요하고, 나머지는 0.90이면 됩니다. 즉 병합 셀의 운전압력은 자동으로 채우지만,
같은 병합 셀의 최대보유량은 사람에게 넘깁니다. 핵심값은 자동 기입했더라도 ‘먼저 볼 핵심값’ 목록에 올라
출처 확인 전까지 보고서에 ‘사람이 아직 보지 않은 값’으로 표시됩니다. 법적 계산에 쓰이는 자동 기입값은 원자료·단위·현재 적용 여부를 사람이 확인하기 전까지 작성자료 연결을 차단합니다.

새로운 출처가 들어오면 해당 사실의 이전 결정(자동 포함)은 무효가 되고 규칙을 다시 적용하며, 연결된 작성자료는 HOLD로 돌아갑니다.

## 순위와 핵심값

예비 비교지표는 `최대보유량(kg) × (1 + 운전압력(MPa)) × 함량(%) / 100`입니다. 물질별 독성·인화성, 누출량, 성상,
차단설비, 날씨, 거리와 보호대상은 반영하지 않으므로 **검토 순서이지 위험도나 법적 판정이 아닙니다.**

값은 세 상태입니다.

- **확정**: 담당자가 확인했거나 규칙이 자동 기입한 값
- **잠정**: 아직 확인하지 않았지만 충돌·오류가 없는 후보값. 순위 계산에 사용합니다.
- **가정**: 값이 없거나 충돌·오류라서 임시값으로 대체한 값. 충돌이면 큰 값(보수적), 값이 없으면 같은 사업장 관측 최고값×1.5와
  보유량 10,000kg·압력 1MPa 중 큰 값, 함량 100%입니다. 안전한 상한이나 물성 추정이 아니며, 가정이 있는 후보는 ‘보류’로 표시하고
  작성자료나 계산에 자동 반영하지 않습니다.

두 가지 민감도를 봅니다.

- **가정 값**: 0 ~ 임시값의 2배로 움직여 순위가 달라지면 그 값을 먼저 물어봅니다.
- **실제 값**: 0.5배·2배로 움직여 순위가 달라지면 *핵심값*으로 표시하고, 자동 기입 문턱을 높입니다.

같은 설비 또는 같은 물질의 값이 여러 조합에 쓰이면 영향을 받는 조합의 점수를 **함께 다시 계산**합니다.
따라서 모든 설비가 한 물질만 다룰 때 그 물질의 함량을 일괄 바꿔도 상대 순위가 같다면 순위 핵심값으로 분류하지 않습니다.
이 비교는 한 값씩만 바꾸는 시험이며, 여러 값이 동시에 틀린 경우의 보증이 아닙니다.

후보가 하나뿐이면 순위 민감도만으로 필요한 자료가 없다고 결론 내릴 수 없습니다. 취급 관계가 여러 물질로 모호하면 보류합니다.

## 읽기 지원 범위

- 제목·안내 줄이 위에 있어도 항목명이 가장 많이 모인 줄(앞 20줄 이내)을 머리글로 읽습니다.
- 엑셀 수식은 저장된 계산 결과를 쓰되 신뢰도를 낮추고, 계산 결과가 없으면 값 오류로 남깁니다.
- 병합 셀은 왼쪽 위 값을 펼쳐 읽되 표시합니다. 숨김 시트도 읽고 시트 이름에 표시합니다.
- 번호 열이 있는 표에서 번호 칸이 빈 줄(합계·메모·번호를 안 적은 설비)은 추측해 붙이지 않고 건너뛰며, 몇 번째 줄에 무엇이 적혔는지 알려 줍니다.
  번호 열이 없는 표만 이름으로 연결합니다(확인을 받음). 연결하지 못한 열은 문서별로 표시하고 사람이 지정할 수 있습니다.
- 표기 목록(동의어)은 미리 늘리지 않습니다. 담당자가 답한 것이 사업장 규칙으로 쌓입니다.
- 두 줄 이상으로 나뉜 머리글, 도면·P&ID, 혼합물 성분 관계의 완전한 모델링은 구현하지 않았습니다.

## 별지 제1호와의 관계

연결한 설비 행은 별지 제1호의 **직접 확인 최대보유량(kg)** 경로로 물질별 합산됩니다. 시설유형·물질성상·용량·비중·공정유형도
읽어 와서 별지 제1호 시설 입력 화면에 미리 채웁니다. 다만 별표 4에 따른 법정 산정(설계용량×비중 등)은 그 화면에서
저장할 때 일어나며, 회사가 적은 최대보유량과 산정값이 다를 수 있으므로 자동으로 이어 붙이지 않았습니다.
아직 필요한 입력은 ④에 계산 엔진의 문장 그대로 표시합니다.

## 로컬 AI

선택 기능입니다. `LOCAL_LLM_PROVIDER`(ollama 또는 openai_compatible), `LOCAL_LLM_URL`, `LOCAL_LLM_MODEL`을 설정하고
대상 식별번호와 함께 PDF/DOCX/HWPX/TXT를 접수한 뒤 ‘로컬 AI 후보 제안’을 누릅니다. 원문에 연속된 인용구, 정확한 위치,
수치 및 같은 단위가 있는 제안만 후보로 접수하며, 접수한 후보도 자동 기입·일괄 확인에서 제외되어 한 건씩 사람이 확인해야 합니다.
문서 원문을 원격 모델로 보내지 않습니다.

## 시험 순서

①의 ‘연습용 가상 회사 자료 받기 (ZIP)’를 내려받아 풀고 네 파일을 한 번에 올립니다. 종류는 자동으로 분류됩니다.

- 02·03번: `TK-01` 용량 10m³/12m³ 충돌 → 사실 표에 ⚠ 충돌, 파일별 수정 요청에 두 파일 위치. 03번을 ‘이 파일 빼기’로 빼면 10m³로 정해짐
- 04번: 제목 줄·빈 줄 아래 머리글, 계산식 칸(=1500+500, 결과 없음) → 계산 결과를 값으로 적어 다시 올리라는 요청, 빈 보유량(RX-02)은 순위 질문
- 나머지는 자동 기입

‘계획서 끝까지 연습 자료’로는 01~06·09 파일만 올려 별지 제1·3~7·9~11호와 서술형이 채워지는지 봅니다(`tests/test_evidence_catalog_reading.py`).

예제 조건은 실제 운전이나 위험평가에 사용할 수 없습니다. 새 화면은 원문 첨부와 구조화 후보를 기존 프로젝트 아래 저장하며
회사 자료·키를 GitHub에 올리지 않습니다. 일반적인 API 주소 조회 외에 업로드 문서 자체를 외부 AI로 보내지 않습니다.

## 큰 연습 자료와 정답표

①의 ‘실제와 비슷한 큰 자료 (파일 7개)’는 가상 회사 1곳(설비 40대, 제품 26개)의 자료입니다(`engine/stage2/demo_company.py`).
정답을 먼저 정하고 거기서 파일을 만들면서 현장에서 흔한 문제 30가지를 일부러 넣었고, ZIP 안의 `answer_key.json`에
정답과 문제 목록이 있습니다. 엑셀 여러 시트·숨김 시트·병합 칸·시트마다 다른 단위(L·ton·kPa)·결과 없는 계산식·합계 줄,
한글 윈도우 인코딩 CSV, 개정 MSDS(DOCX), 문장으로 적힌 설비 사양서(HWPX), 스캔 PDF가 들어 있습니다.
06 사양서는 표에 번호가 없으므로 올릴 때 그 파일의 번호 칸에 `RX-205`를 적습니다.

`tests/test_demo_company.py`가 정답표로 채점합니다.

- 처음 읽었을 때 자동 기입한 값 중 정답과 다른 값은 일부러 넣은 띄어쓰기 오류(‘가상자일렌’) 1개이며, 물질 목록과 연결되지 않는다고 따로 알립니다.
- 그대로 쓸 수 없는 칸 50여 개가 질문 13개로 묶입니다. 모르는 머리글 1개를 지정하고 질문마다 한 번씩 답하면(25번 미만) 모두 해결됩니다.
- 같은 시험 파일에 프로그램 코드와 예시 자료 어디에도 없는 표기(`Liquid`, `liq.`, `N/A`, `확인중`)·머리글(`Tag No.`, `Phase`, `농도(%)`)·
  단위 없는 열을 넣어도 같은 방식으로 묻고 적용되는지 확인합니다(`UnseenInputTests`).

이 채점은 우리가 만든 가상 자료에 대한 것이므로 실제 회사 자료의 정확도를 뜻하지 않습니다. 공개 MSDS 등 실제 문서로 같은 방식의 정답표를 만들어 재는 것이 다음 단계입니다.

## 물질·설비 사실은 한 곳에서

같은 물질·설비 사실이 자료 접수 기록과 별지 제1·6호 작성대 표에 따로 있으면 값이 갈라집니다
(예전에는 별지 제1호에서 한 번 저장하면 그 표가 우선이라, 이후 자료 접수에서 보낸 새 값이 조용히 무시됐습니다).
그래서 **자료 접수 기록을 기준**으로 두 쪽을 맞춥니다.

- **별지 → 자료 접수**: 별지 제1호(설비명·취급물질·용량·시설유형·성상·비중·운전압력·운전온도·공정유형)와
  별지 제6호(물질명·CAS·함량·물질상태·비중), 물질 목록 파일 올리기에서 바뀐 값은 자료 접수 기록에
  ‘별지 제1호 직접 입력’ 같은 출처로 확인 완료 상태로 적습니다. 같은 값이면 아무것도 적지 않습니다(취급제품은 제품코드와 이름을 같은 것으로 봄).
- **자료 접수 → 별지**: ④에서 보낼 때 표를 덮어쓰지 않고 같은 설비번호·CAS 번호의 행에 **합칩니다**.
  별지에서만 적는 칸(분자량·형상 치수·직접 확인 최대보유량 등)은 그대로 두고, 새 설비·물질은 뒤에 붙이며,
  별지 제1호 표는 다시 저장해 최대보유량을 다시 계산합니다. 자료마다 달라 아직 정하지 않은 값은 옛 값을 남기지 않고 비웁니다.
- **지우기**: 별지에서 행을 지우면 자료 접수에서도 그 대상을 제외해 다시 보내지 않습니다. ④의 ‘별지에서 지워 제외한 대상’에서 되살릴 수 있습니다.
- 별지에서 고친 값과 다른 값이 나중에 올린 자료에 있으면 ‘자료마다 값이 달라요’ 질문이 됩니다.
- 동기화가 실패해도 별지 저장 자체는 막지 않습니다.

## 계획서 끝까지 연습 자료

①의 ‘계획서 끝까지 연습 자료 (파일 11개)’는 제품 3개·설비 4대의 작은 가상 회사(`engine/stage2/demo_full_company.py`)입니다.
별지 제1~16호와 서술형에 넣을 값이 모두 회사 문서(제품목록·설비대장·사업장 일반정보·공정설명서·SDS 물성표·설비사양/확산방지설비/감지기·
주변 보호대상 조사표와 지도·사고시나리오 검토자료·안전관리/비상대응계획)로 들어 있고, ZIP 안의 `README_테스트_안내서.txt`가
어느 파일의 어느 시트를 어느 화면에 넣는지 순서대로 알려 줍니다.

`tests/test_demo_full_company.py`가 안내서대로 처음부터 끝까지 가 봅니다. 자료 접수에서 질문이 없고, 회사가 넣는 모든 별지의
부족 항목이 0이 되며, 사고시나리오 4건의 피해반경이 계산되고, 규정서식 DOCX에 회사 값이 들어갑니다. 끝에 남는 것은
법령 기준표(별표 1~4) **승인 DB**가 있어야 풀리는 항목과 ‘사업장 판정과 연결’ 검토 안내뿐입니다.
이는 별지 작성대와 검토용 DOCX에 대한 시험입니다. 별도의 전체 완성도 점검에서는 도면 이외에도 작성대와
서로 다른 저장 키를 찾는 항목이 남아 최종 작성본 상태로 통과하지 않습니다. ZIP에 넣은 `answer_key.json`으로
물질·설비·사고시나리오 입력을 대조할 수 있으며, 실제 주소 판의 주변 대상 정답은 비워 둡니다.
승인 DB는 ‘규정 DB 관리 > 최신본 업데이트’로 만들며, 그래야 최대보유량 계산·사고시나리오 대상 판정(별지 제12호 제안 목록)·별지 제6·7호 물질구분과 고유번호가 나옵니다.

**실제 주소로 해 보기**: 내려받기 위의 ‘실제 주소로 해 보기’에 도로명주소(와 산업단지명)를 넣으면 이 가상 회사가 그 주소에 있다고 보고
자료를 만듭니다. 주소는 저장소에 넣지 않고 내려받을 때만 씁니다. 이때는 지어낸 주변 보호대상 목록·지도를 빼고(07 조사표는 빈 양식),
안내서가 별지 제8호를 회사에서 처음 쓸 때처럼 ‘사고시나리오 결과’ 화면에서 ‘주소 필지 경계 불러오기 → 지도에서 고쳐 그리기 → 주소로 주변 지도 조회 →
주변 보호대상 조사표 내려받기 → 분류·거리 고쳐 다시 올리기’ 순서로 안내합니다. 지도 조회에는 `VWORLD_API_KEY`·`VWORLD_DOMAIN`(카카오 장소명은 `KAKAO_REST_API_KEY`)이
필요합니다. 회사·설비·운전값은 그대로 허구이므로 장외 영향 결과만 실제 주변에 따라 달라집니다. 같은 테스트 파일의 `RealAddressTests`가
지도 조회 응답을 흉내 내어 이 순서로 끝까지 가 봅니다.

**현장형 예외 시험은 별도 사업장에서 진행합니다.** ①의 ‘회사 자료처럼 복잡한 파일로 별도 시험하기’에서
정답표가 든 ZIP을 받으세요. 공장 A/B가 같은 설비번호를 쓰고, 한 제품에 CAS 성분 2개가 있으며,
구버전과 개정 설비자료, CP949 CSV와 DOCX 운전기록이 섞여 있습니다. 실제 정답은 설비 3대와 성분 2개입니다.
현재 추출기는 중복 설비번호를 합치고 두 성분을 CAS 충돌로 표시합니다. `NonDrawingAuditTests`는
이 알려진 결함과 도면 제외 후 남는 작성항목을 확인하며, 성공으로 간주하지 않습니다.

이 자료로 끝까지 가 보면서 고친 것: 별지 제8호 지도·별지 제11호 감지기 근거 파일이 점검이 보는 곳에 붙도록 함(제11호에 근거 파일 연결 추가),
별지 제6호에 분자량 칸(사고시나리오 계산에 필요) 추가, ‘결과를 별지 제12·13호에 반영’ 때 프로그램이 만든 영향범위 분석 근거서를 보관·연결,
설비대장에 비중이 없으면 취급물질의 비중을 별지 제1호 계산에 씀.

## 사고시나리오 결과 (별지 제8·12~15호, 공정안전보고서 별지 제19호의2)

사람은 시나리오를 화면에서 고르거나 숫자를 적지 않습니다. 회사 파일이 바뀌면(올리면) 결과도 다시 계산됩니다.

1. **대상 설비·사고유형**: 설비대장·제품목록·SDS 물성표로 규정수량을 비교해(규정 제23조, 별표 2) 대상 설비를 정하고, 급성독성 구분이 있으면
   독성 누출, 폭발한계가 있으면 화재·폭발을 봅니다. ‘사고시나리오 검토자료’ 파일의 ‘선정할 사고유형’ 열이 있으면 그 값이 먼저입니다
   (‘선정 안 함’으로 뺄 수 있고, 규정수량 대상이 아닌 설비도 넣을 수 있음). 알아볼 수 없는 값은 어느 파일·열을 고칠지 알려 줍니다.
2. **계산 입력**: 같은 파일의 ‘경계까지 거리(m)’(필수), 액위·누출지점 배관길이·비열비·연소열·비점·액체비열·기화열·액화가스 물성.
   연결구·운전압력·온도·비중·분자량·증기압은 이미 올린 설비사양·SDS 물성표에서 씁니다.
3. **보호대상**: ‘주변 보호대상 조사표’(보호대상 시트 + ‘조사 방법’ 항목·값 시트)에서 읽어 별지 제8호 목록과 지도·현장 확인 기록에 넣습니다.
   조사표는 사고시나리오 결과 화면에서 내려받으며, 지도에 그린 사업장 경계에서 잰 거리와 이름 규칙(있으면 로컬 AI) 분류 제안이 미리 적혀 있습니다.
   AI 제안 중 법정 분류 목록에 없는 값은 버립니다.
4. **결과**: 피해반경·장외거리(`cap_release_workspace`)와 영향범위 안 보호대상·인구(`cap_impact_workspace`)를 별지 제12·13호에, 장외 시나리오의
   개시사건 개수·완화장치를 별지 제14호에 넣고 위험도(별지 제15호)를 판정합니다. 영향범위 분석 근거서 DOCX를 함께 만듭니다.
   공정안전보고서 대상이면 같은 시나리오로 별지 제19호의2를 계산합니다. 최악·대안은 파일의 ‘공정안전보고서 시나리오 구분’이 먼저이고, 비어 있으면
   단위공장·사고유형마다 피해반경이 가장 큰 시나리오를 최악으로 씁니다. 대기온도·습도는 사업개요 파일 값이 먼저이고, 없으면 화면을 처음 열 때
   주소로 고른 기상청 관측소의 지난 3년 자료로 채웁니다.
5. **선정 근거 문장**: 회사 파일의 ‘시나리오 선정 근거’가 있으면 그대로, 없으면 규정수량 판정으로 쓴 문장입니다. 로컬 AI로 다듬을 수 있고,
   규칙 문장에 없는 숫자·설비번호는 `[확인 필요]`로 바뀝니다. 규칙 문장이 바뀌면(파일 변경) AI 문장은 쓰지 않습니다.

모든 결과는 메모가 ‘공통정보 연결’로 시작해 파일을 새로 올리면 보류로 바뀌고, 자료 올리기 화면 또는 사고시나리오 결과 화면이 열릴 때 다시 계산됩니다.
