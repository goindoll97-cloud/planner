# 자료 중심 업무 공간

프로그램의 기본 시작 화면은 ‘자료 접수·확인할 일’입니다. 기존 별지 작성·법적 대상 판정·계산 엔진은 유지합니다.

1. 새 사업장 또는 기존 프로젝트를 선택합니다. 새 프로젝트 생성은 작성자료 정리를 시작하는 것이며 법적 제출 대상 판정을 대신하지 않습니다.
2. 설비 자료와 물질 자료를 각각 업로드합니다. CSV·XLSX의 표와 DOCX·텍스트 PDF의 표를 읽습니다. PDF·DOCX·TXT의 원문도 위치와 함께 보존합니다.
3. 표의 설비번호/제품코드를 우선 사용합니다. 코드가 없으면 명칭을 사용하므로 동명이거나 이름이 다른 대상은 담당자가 식별해야 합니다. 자유서술을 임의로 같은 설비에 연결하지 않습니다.
4. 같은 대상·항목에 서로 다른 값이 있으면 충돌로 남깁니다. 파일명·SHA256·시트/페이지·행·열과 원문을 대조해 사용할 값을 확인합니다. 범위·수식·단위 불명확 값은 임의 숫자로 승인할 수 없습니다.
5. 부족한 값은 근거와 함께 후보로 추가합니다. 새로운 출처가 들어오면 해당 사실의 이전 결정은 다시 확인해야 하며 연결된 작성자료는 HOLD로 돌아갑니다.
6. ‘공통정보 연결’에서 기존 목록과 새 값을 비교한 뒤 반영합니다. 다른 기존 목록을 교체하려면 교체 확인을 명시적으로 선택해야 합니다. 출처와 결정은 별도로 보존됩니다.
7. ‘시나리오 후보’에서 물질×설비 조합을 전부 펼쳐 취급 관계를 확인합니다. 확인된 관계만 예비 순위를 부여하고 연결 근거가 없는 조합도 삭제하지 않고 보류합니다. 결측값은 상향 가정을 표시하고 변수별로 순위 변동을 검사해 순위에 영향을 주는 질문부터 보여줍니다.
8. ‘계산·보고서’에서 설비별 기본조건·출처·남은 조건을 검토하고 기존 계산 화면으로 이동합니다. 검토 보고서와 결정 기록을 내려받을 수 있습니다.

## 신뢰도·AI 후보·자동 기입

명확한 설비번호가 있는 표에서 단일한 설비명만 자동 기입합니다. 수치, 취급제품, 물질명, CAS, 함량은 자료가 같아도 담당자 확인을 요청합니다. 출처 충돌, ID 부재, 문장 추출, 로컬 AI 제안도 보류합니다. 출처가 바뀌면 이전 결정과 연결된 자료를 다시 확인해야 합니다. 신뢰도는 표+명확한 ID 0.98, 이름만으로 연결한 표 0.78, 직접 표시된 문장 0.88, 로컬 LLM 0.55로 추출 경로의 *검토 우선순위*를 나타내며 실제 정확도나 법적 증명력이 아닙니다.

로컬 AI는 선택 기능입니다. `LOCAL_LLM_PROVIDER`(ollama 또는 openai_compatible), `LOCAL_LLM_URL`, `LOCAL_LLM_MODEL`을 설정하고, PDF/DOCX/TXT를 대상 식별번호와 함께 접수한 뒤 ‘로컬 AI 후보 제안’을 누릅니다. 원문에 연속된 인용구, 정확한 위치, 수치 및 같은 단위가 있는 제안만 수락합니다. 수락은 후보 접수일 뿐 승인이 아닙니다. 로컬 서버가 없으면 표 기반 기능만 사용합니다. 문서 원문을 원격 모델로 보내지 않습니다.

## 순위와 결측 처리의 의미

예비 비교지표는 `최대보유량(kg) × (1 + 운전압력(MPa)) × 함량(%) / 100`입니다. 실제 물질별 독성·인화성, 누출량, 성상, 차단설비, 날씨, 거리와 보호대상은 반영하지 않습니다. 임시 결측값은 같은 사업장의 확인된 최고값×1.5 또는 보유량 10,000kg·압력 1MPa 중 큰 값, 함량 100%입니다. 이는 **검토 누락을 줄이기 위한 상향 임시값**이지 실제 설비의 안전한 상한, 물성 추정, 보수적인 공식 피해예측값이 아닙니다. 따라서 ‘가정’과 ‘보류’를 표시하고 기존 시나리오·법정서식에 자동으로 반영하지 않습니다.

한 번에 한 결측값을 `0 ~ 임시값의 2배`(함량은 최대 100%)로 바꿔 취급 관계가 확인된 다른 조합과의 등위가 달라지는지 검사합니다. 변하는 결측값은 먼저 질문합니다. 변하지 않는 값도 실제 시나리오 선정·모델 입력 전에 확인해야 합니다. 후보가 하나뿐이면 순위 민감도만으로 필요한 자료가 없다고 결론 내릴 수 없습니다. 취급 관계가 여러 물질로 모호하면 보류합니다.

가상 회사 ZIP에는 물질대장, 현재 설비대장, 용량이 다른 구버전 설비대장이 있습니다. 압축을 푼 후 물질 파일은 제품·물질 자료로, 나머지 두 파일은 설비 자료로 올리면 용량 10m3와 12m3 충돌이 나타납니다. 예제 조건은 실제 운전이나 위험평가에 사용할 수 없습니다.

확인된 공통정보는 `inventory.chemicals`와 `inventory.facilities`에 연결합니다. 기존 CAP 작성대에 별도로 편집한 시설 정보가 있으면 기존 프로그램의 우선순위가 유지됩니다. 연결 화면과 기존 작성대의 차이를 검토해야 합니다.

## 현재 구현 범위와 남은 개편

이 버전은 공통 사실·출처·충돌·결정·질문·연결 구조를 도입하고 표 기반 자료 읽기를 연결한 단계입니다. 본문에서 규칙으로 자동 인식하는 것은 대상 ID를 지정한 명확한 ‘항목: 값’ 문장입니다. 로컬 LLM은 인용 가능한 자유서술을 선택적으로 제안합니다. 스캔 OCR, HWP/HWPX·도면 인식, 혼합물 성분 관계의 완전한 모델링은 구현하지 않았습니다. 인식 실패와 연결되지 않은 열은 표시합니다.

시나리오 후보 순위와 입력 검토팩은 검토 순서이며 자동 시나리오 선정이나 계산 완료가 아닙니다. 누출·안전설비·물성·모델 조건은 별도 검토합니다. 법적 판정이나 계산을 LLM의 추정으로 대체하지 않습니다. 공식 시나리오 선정은 기존 CAP/PSM 흐름에서 검증된 조건과 해당 기술지침에 따라 처리해야 합니다.

새 화면은 원문 첨부와 구조화 후보를 기존 프로젝트 아래 저장하며 회사 자료·키를 GitHub에 올리지 않습니다. 일반적인 API 주소 조회 외에 업로드 문서 자체를 외부 AI로 보내지 않습니다.
