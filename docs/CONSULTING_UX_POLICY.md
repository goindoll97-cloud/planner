# Consulting-first UX policy

이 프로그램의 회사 사용자 화면은 법령 용어를 단순히 나열하는 조회도구가 아니라, 처음 업무를 맡은 신입사원도 다음 행동을 이해할 수 있는 **사전진단·컨설팅 화면**을 목표로 한다.

## 기본 원칙

모든 법적 질문·경고·판정보류 항목은 가능한 한 아래 순서로 안내한다.

1. **현재 왜 이 질문이 나왔는가**
   - 이전 단계에서 무엇이 확인되었기 때문에 추가 확인이 필요한지 먼저 설명한다.
2. **용어를 쉬운 말로 설명한다**
   - 사용자가 법령 용어를 이미 알고 있다고 가정하지 않는다.
3. **회사가 실제로 무엇을 확인하면 되는지 제시한다**
   - SDS, 저장탱크, 반응기, 보관계획도, 업종코드 등 확인 위치나 자료를 구체화한다.
4. **대표 사례 또는 선택 가능한 법정 유형을 보여준다**
   - 법에서 유형이 정해져 있으면 화면에서 직접 목록을 제공한다.
5. **법적 근거를 함께 제공한다**
   - 법령명, 조문, 별표·비고 등을 표시하되 본문 설명보다 앞세우지 않는다.
6. **이 답변이 판정에 어떤 영향을 주는지 설명한다**
   - 대상/비대상/제외/다음 단계/판정보류 중 어디로 이어지는지 알려준다.
7. **모르면 추정시키지 않는다**
   - 항상 `모름`, `확인 필요` 또는 이에 준하는 선택지를 제공하고, 법적 사실이 부족하면 `판정보류`한다.

## 표시 우선순위

일반 사용자 화면에서는 다음 순서를 따른다.

**결론의 의미 → 필요한 행동 → 쉬운 설명 → 예시 → 법적 근거 → 전문가용 상세**

`별표 1`, `별표 2`, `별표 3`, `별표 4`, `R`, 내부 상태코드 등은 설명 없이 단독으로 노출하지 않는다. 필요한 경우 먼저 풀어 쓰고, 상세 근거에서 정확한 법령 용어를 보여준다.

## 질문 생성 원칙

회사가 이미 입력한 사실은 다시 묻지 않는다. 프로그램이 보유 데이터를 우선 사용하고, 결정에 필요한 사실 중 실제로 누락된 것만 동적으로 질문한다.

예:

- PSM 규정량 기준이 충족된 경우에만 제외설비를 확인한다.
- 화학사고예방관리계획서 규정수량 대상물질이 확인된 경우에만 최대보유량을 확인한다.
- 별표 2·3 직접 규칙으로 결론이 나지 않는 물질에 한해 SDS 유해성·위험성 분류를 확인한다.
- CAS 하나로 특정할 수 없는 법적 물질군에 한해 포괄범위 확인을 요청한다.

## 판정보류 원칙

`판정보류`는 실패가 아니라 안전한 결과다. 화면에는 반드시 다음을 함께 표시한다.

- 무엇이 아직 확인되지 않았는지
- 회사에서 어디를 보면 확인할 수 있는지
- 확인 후 어떤 판정을 다시 수행하는지
- 가능한 경우 법적 근거와 원문 위치

## 구현

공통 설명은 `engine/consulting_guidance.py`의 가이드 카탈로그를 사용한다. 새로운 법적 질문을 추가할 때는 판정 로직만 추가하지 말고, 해당 질문에 대한 컨설팅 가이드도 함께 추가한다.
